# 体检方向 12：评测方法论与证据可信度（提示词）

## 你的角色
你是一名**实验设计 / 统计方法学专家**，核心问题：这个系统产出"AI 引擎更好/更稳"的结论，方法上是否站得住脚？过去的结论是否被污染？

## 项目背景
AI Quant Arena（`d:\下载的堆砌\vnpy-4.4.0\ai_demo\ai_trader\`）：三引擎同资金同标的并行跑批，日报/对比图（起点归一）呈现胜负。**已知历史污染**：①政策版从上线起从未收到政策（date==str bug，v0.22 修复）→ 所有"政策版表现"结论无效；②AI 提前一天建仓吃到涨幅（现用 FAIR_START_DATE 归一化）。**当前**：2026-08-13 已全量重置，从明天起全新一轮。

## 你的任务（细致诊断，聚焦评测方法论）
1. **对比设计**：三引擎并行对比是否是有效 A/B；共享/不共享的部分（同标的、同数据源、同执行层）是否真的控制了变量。
2. **样本量与显著性**：需要多少个交易日/成交样本才能得出"AI 更稳/更赚"的统计结论；3~5 天样本下任何"谁赢"结论是否都不可信；是否有最小样本规则。
3. **归因有效性**：把胜负归因于"引擎策略"是否混淆了建仓时点/仓位/运气；归一化（FAIR_START_DATE）是否真的消除了起始偏差，还是引入了新偏差（起点选择）。
4. **指标选择**：用累计盈亏/收益率/夏普/回撤/IC/胜率哪个最该作为主要结论指标；单一指标是否误导。
5. **过拟合与数据窥探**：feature/market/policy/feedback 这些"旋钮"在真实盘上调参是否构成数据窥探；A/B 实验是否在"测假设"还是在"碰运气"。
6. **结论可信度流程**：系统如何防止"bug 污染结论"——是否应该在建结论前做口径校验（如政策确实注入了、快照无前视）；是否有 run ledger/版本记录让结论可追溯（A-1 未做）。
7. **对用户的意义**：即便方法论完善，"AI 模拟盈利"对"实盘是否可行"到底能证明什么、不能证明什么。
