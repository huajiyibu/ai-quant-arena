# 体检方向 05：运维与稳定性（提示词）

## 你的角色
你是一名**量化系统 SRE / 运维专家**，关注无人值守的每日自动跑批是否可靠：定时任务、崩溃恢复、告警、监控、成本控制。

## 项目背景
AI Quant Arena（`d:\下载的堆砌\vnpy-4.4.0\ai_demo\ai_trader\`）：Windows 下通过计划任务（`scripts/install_task.ps1`，已接 `--catch-up`）每日 15:30 跑 `run.py`，Webhook 告警（`aitrader/notify.py`），运行日志在 `data/logs/`，`data/last_run.json` 记录上次运行。

## 你的任务（细致诊断，聚焦运维稳定性）
1. **定时任务**：`install_task.ps1` 参数是否完整（--catch-up）、重启后是否自愈、是否会重复运行（run.lock 机制是否可靠）。
2. **崩溃恢复**：进程崩溃/关机跨天后的恢复路径（N-2 只认 done、N-9 catch-up、幂等）；是否有"半写"风险（P0-4 事务未做）。
3. **告警**：`notify.py` 的检查项（失败/无成交/回撤）是否真的能触发（历史 P0-3 回撤告警永不触发的回归教训）；Webhook 失败是否静默。
4. **监控与自检**：是否有 `--health` 自检（P1-2 未做）；如何发现"引擎空转/数据陈旧/整天被剔除"。
5. **成本控制**：DeepSeek API 成本是否有累计记账（P1-6 未做）；缓存是否真的省了钱；是否有预算上限。
6. **日志与可观测**：`data/logs/` 是否覆盖关键事件、是否滚动、是否够排查问题。

## 可用手段
- 代码：`run.py`、`aitrader/notify.py`、`scripts/install_task.ps1`、`scripts/check_daily.py`、`aitrader/database.py`（batch_runs/run.lock）。
- 真实运行：`data/logs/`、`data/last_run.json`、`data/run.lock`、任务计划（`schtasks` 可查）。
- 文档：`docs/IMPROVEMENTS.md` 的 N-2/N-9/P1-2/P1-6/P0-4 记录。

## 重点怀疑（请逐一核实，但不受限于此）
- **P1-2 --health 自检**：系统没有任何"我是否健康"的自检入口。
- **P1-6 成本记账**：API 成本没有累计（只有单次 api_calls 计数）。
- **run.lock**：崩溃后锁是否可能残留导致下次不跑。
- **告警链路**：`check_alerts` 的调用方传参是否又是"只传单元素"之类的回归（历史 P0-3 教训）。
- **catch-up 正确性**：跨周末/节假日/关机后的补跑是否会重复或漏跑。
