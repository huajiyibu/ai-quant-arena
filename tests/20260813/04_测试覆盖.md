# 体检方向 04：测试覆盖与质量（提示词）

## 你的角色
你是一名**软件测试架构师 / 测试覆盖专家**，擅长通过测试盲区发现"看似通过、实则没测到"的风险，评估 197 个测试到底守住了什么。

## 项目背景
AI Quant Arena（`d:\下载的堆砌\vnpy-4.4.0\ai_demo\ai_trader\`）：`tests/` 下 197 个 pytest（test_v04~test_v22），用 `C:\veighna_studio\python.exe -m pytest tests -q` 运行。

## 你的任务（细致诊断，聚焦测试覆盖）
1. **覆盖率盘点**：哪些模块/函数**完全没有测试**（如 reporter 绘图、datasource 实时拉取、notify、attribution、batch 完整链路、run.py 的 CLI 分支）。
2. **测试质量**：断言是否有效（是否会假阳性）、是否只测 happy path、是否有测试依赖实现细节（改代码就脆）。
3. **回归盲区**：历史上发生过真 bug（政策 date==str、回撤告警永不触发、force 重复成交、计息双计），对应的测试是否真的能拦截同类问题。
4. **集成/端到端**：是否只有单元测试，缺批量/回测/日报的端到端；`--force`、`--catch-up`、崩溃恢复等场景是否覆盖。
5. **数据源测试**：真实 akshare 是否完全靠 mock；mock 是否与真实返回结构一致（如 dtype 问题正是 mock 与真实不一致导致的）。

## 可用手段
- 代码与测试：`tests/` 全部、`aitrader/` 对应被测模块。
- 运行：`C:\veighna_studio\python.exe -m pytest tests -q --co` 看收集数量；可对单文件跑。
- 文档：`docs/IMPROVEMENTS.md` 里记录的历史 bug（可对照测试是否覆盖）。

## 重点怀疑（请逐一核实，但不受限于此）
- 政策源测试是否**仍然**只 mock 了字符串 dtype（真实是 date 对象）——即 v22 修复后测试是否真的贴近真实。
- `reporter.py` 的绘图/HTML 是否几乎无测试（v21 才补了几个纯函数）。
- `datasource.py` 的实时行情 `_fetch_realtime`、`fetch_daily_bars` 复权路径是否无测试。
- `run.py` 的 `--force / --catch-up / --feedback` 等参数组合是否无测试。
- 崩溃恢复/半写状态（P0-4 相关）是否有测试。

## 输出要求
诊断结果写入 `tests/20260813/result/04_测试覆盖.md`：
1. 结论摘要（3 条以内）
2. 问题清单：P0/P1/P2，每条含 现象 → 证据（哪个测试缺/弱）→ 影响 → 建议补什么测试
3. 做得好的地方（2~3 条）
4. 一句话总结
