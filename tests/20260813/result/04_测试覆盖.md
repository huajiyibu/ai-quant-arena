## 1. 结论摘要

1. **197 个测试全过、核心链路（批处理/回测/风控/账本/引擎）守得扎实**，但几乎全是"单元 + 局部集成"——**没有任何一个测试调用 `run.py` 的 `main()` / `_run()` / `run_backtest()` 完整 CLI 入口**。`--force`、`--catch-up`、`--report-only`、`--backtest`、`--db`、单实例锁竞争等"参数接线"层全部裸奔，十几个 `run_backtest` 的 `args→settings` 覆盖分支（`--fill/--slippage/--commission-mult/--stop-loss/--feedback` 等）无测试兜底。
2. **三大真实盲区**：① reporter 绘图函数 `plot_compare` / `plot_backtest_curves` **零测试**，日报 `build_daily_report` 只在"`fetch_daily_bars` 必抛错"的 mock 下测过标记子串（基准成功路径从未执行）；② 真实数据源 `AkShareDataSource.fetch_daily_bars(..., adjust="hfq")` 复权组装与 `_load_trade_calendar` / `is_trading_day` / `calendar_ok` 无测试（v07 只断言 hfq 被"透传"）；③ **P0-4 崩溃写中途**只有"写快照前崩溃"的 N-2 用例，没有"成交已写入后崩溃 → 重跑去重 → 恰好一套成交"的端到端回归。
3. **历史四个真 bug（政策 date==str、回撤告警永不触发、force 重复成交、计息双计）都有针对性回归测试且质量不错**（v22 已用真实 `date` 对象 dtype）；但**政策源 mock 的"发布时间"列 dtype 在 v09（str）与 v22（time）之间不一致**，暴露"mock 未锁定真实 akshare schema"的同类风险仍存在。

## 2. 问题清单

### 🔴 P0

#### P0-1 `run.py` CLI 入口零端到端测试
- **现象**：`main()` / `_run()` / `run_backtest()` 从未被测试调用；CLI 只测了被抽出的纯函数。
- **证据**：grep `tests/` 无 `main(`/`_run(`/`run_backtest(` 调用；仅 `_date_type`（v04/v10）、`select_daily_engines`/`select_backtest_engines`（v02/test_backtest）、`_catch_up_dates`（v14）、`write_last_run`（v14/v17）、`_maybe_notify`（v19）被单独测。`--report-only` 分支、`--backtest` 分支、单实例锁竞争分支（"另一实例正在运行"）、`--db` 覆盖、`run_backtest` 内 13 个 `args→settings` 覆盖（v05/v07/v15 只测了引擎层逻辑，没测参数接线）、`_last_closed_trading_day`（P1-11 已知无日历守卫）全部未覆盖。
- **影响**：参数接线错了没有任何测试能拦（P2-12/P2-13 的"CLI help 与 config 默认漂移"正落在这层）；`--force`/`--catch-up` 的真实触发路径、`last_run.json` 的端到端写入无人验证；回测 `--db` 误污染每日账本（P2-1）也无护栏。
- **建议**：新增 CLI 端到端用例：monkeypatch 掉 `AkShareDataSource`/DeepSeek 网络后调用 `main(["--date", "2024-01-02", "--force"])`，断言退出码、`last_run.json` 字段、报表文件生成；覆盖 `--report-only`、`--backtest`（含 `--fill/--slippage/--commission-mult` 覆盖后 settings 值）、锁竞争（先 `acquire()` 再 `main()` → 退出码 0 + 输出"另一实例"）、`--db` 隔离。

#### P0-2 P0-4 崩溃写中途（成交已写入、`complete_batch_run` 未执行）无端到端回归
- **现象**：v0.20 用 `trades` 唯一约束 + `INSERT OR IGNORE` 修复了"崩溃重跑重复成交"，但**没有测试模拟 `_run_engine` 写路径中途崩溃**。
- **证据**：`test_v12::test_stale_running_gets_rerun` 只覆盖 `begin_batch_run` 后**尚无成交**时的崩溃（N-2 场景）；`test_v20::test_add_trade_idempotent_on_duplicate` 只测数据库层 `add_trade` 去重，未走 `_run_engine` 全链路。无人验证"`add_trade` N 笔后进程死掉 → 库中留 `running`+部分 trades+无快照 → 重跑后恰好一套成交"。
- **影响**：这是 IMPROVEMENTS.md 明示的无人值守风险窗口，v0.20 的修复完全依赖"唯一约束+重跑覆盖"，但**没有回归护栏**；后续 `Database.transaction()` 原子化（IMPROVEMENTS 建议）也缺验收测试。
- **建议**：补集成用例：monkeypatch `db.add_trade` 在写入 N 笔后抛异常 → 断言重跑后 `trades` 恰一套（唯一约束生效）、无半写快照、`batch_runs` 最终为 done；若做 `transaction()` 原子化，以该用例为验收。

### 🟡 P1

#### P1-1 reporter 绘图 / HTML 主路径测试缺失（含已知 P1-10 段）
- **现象**：`plot_compare`、`plot_backtest_curves` 完全没有测试；`build_daily_report` 的**基准对照成功路径**从未执行。
- **证据**：grep 无任何测试 import `plot_compare`/`plot_backtest_curves`；v11/v12/v17/v18 的日报测试全部 `monkeypatch(AkShareDataSource.fetch_daily_bars, raise)` → `bench_line` 永远走空串分支。P2-4（资金曲线 1e6 轴口径）、P1-10（基准实时联网+未复权+500 根硬编码+失败静默）正落在这段未测代码上。
- **影响**：图表/基准对照在真实网络下可能产出错误或崩溃；`plot_backtest_curves` 的回撤面板逻辑（`peak` 计算）改动极易回归；P1-10 的"基准失败应可见而非静默留空"无人验证。
- **建议**：① `plot_backtest_curves` 用构造好的 db+快照测"文件生成 + 回撤面板数值正确"；② `build_daily_report` 增加基准**成功**路径（mock `fetch_daily_bars` 返回确定性 bars，断言 `bench_line` 含具体百分比）与**失败可见**路径（P1-10 落地后断言非静默）。

#### P1-2 真实数据源复权 / 交易日历路径无测试
- **现象**：`AkShareDataSource.fetch_daily_bars(..., adjust="hfq")`（内部 `fetch_dividends` + `compute_adjusted_bars` 组装、失败降级）与 `_load_trade_calendar` / `is_trading_day` / `calendar_ok` 的真实实现无测试。
- **证据**：`test_v07` 用 `RecordingDS(FakeDataSource)` 只断言 `adjust="hfq"` 被**透传**给数据源，没跑真实 hfq 组装（`FakeDataSource` 忽略 adjust）；日历只测 `FakeDataSource` 与带 `calendar_ok` 属性的假包装类（v04/v09）。
- **影响**：真实复权拉分红失败降级、日历缓存失败降级这两个"真实环境分支"无保护；P1-4（交易日历无本地缓存/无重试）、P1-3（单数据源单点故障）这类问题测试无法发现。
- **建议**：mock `ak.fund_etf_hist_sina` + `ak.stock_zh_a_dividend` 直接调 `AkShareDataSource.fetch_daily_bars(adjust="hfq")` 断言输出已复权；mock `ak.tool_trade_date_hist_sina` 测 `is_trading_day`/`calendar_ok` 的成功与失败降级两分支。

#### P1-3 政策源 mock 的"发布时间"列 dtype 不一致（v09 str vs v22 time），未锁定真实 schema
- **现象**：同一列"发布时间"在两个测试里 dtype 不同——`test_v09::_policy_df` 用 `str "09:00:00"`，`test_v22::_df` 用 `dt.time`；"发布日期"统一为 `date`。
- **证据**：两文件对同一 akshare 列给出不同 dtype；真实接口若该列为 `Timestamp/datetime`，`df["发布时间"].astype(str).str[:5]` 会把 `"2026-08-10 09:30:00"` 截成 `"2026-"`，恒 `> "15:30"` → **全天政策被静默滤空**（正是 v22 修复那类 bug 的变体）。
- **影响**：v22 修复后"dtype 陷阱"仍未制度化防复发；akshare 升级改 dtype 时可能静默回归且无测试拦截。
- **建议**：统一 policy mock 为贴近真实的 dtype（以 v22 为准），并补一条"发布时间为 `datetime`/`Timestamp` 对象"的反向用例证明代码仍正确；最好把该 DataFrame 提为 `tests/conftest.py` 共享 fixture，锁死 schema 供两文件复用。

#### P1-4 通知 `send_notify` 成功路径未测
- **现象**：`send_notify` 只测了"失败不抛"（空 url / 无效地址 `http://127.0.0.1:1/nope`），POST JSON 成功、Server酱 GET 降级、`r.ok` 判定均未覆盖。
- **证据**：`test_v14::test_send_notify_failure_does_not_raise` 仅两分支；`check_alerts` 各条件有覆盖（v14/v19）。
- **影响**：通知是无人值守发现异常（P0-5 计息、数据挂）的唯一出口，成功路径无护栏；若 webhook 格式/降级顺序改坏会静默失效。
- **建议**：mock `requests.post`/`requests.get` 返回 `ok=True/False` 各分支，断言返回 True/False 与"POST 失败→GET 降级"顺序。

#### P1-5 `reset_account` 等 DB 函数无直接测试
- **现象**：`database.reset_account`、`state_to_dict`/`state_from_dict` 无直接用例；`get/set_last_interest_date` 只经 batch 间接覆盖。
- **证据**：grep 确认 `reset_account` 在 tests/ 中零引用。
- **影响**：`reset_account` 是回测独立库/清账本的关键路径，改坏会污染账本且无拦截。
- **建议**：补 database 层小用例：reset 后账户现金回到初始资金、快照/trades 清空、状态序列化往返一致。

### 🟢 P2

#### P2-1 部分断言偏弱（子串级）且无量化覆盖率门禁
- **现象**：多数日报测试只断言 HTML 含某子串（`"今日决策"`、`"数据截至"`、`"货基利息累计"`），属冒烟级；`test_v12` 分桶断言到具体行（`<tr><td>0.7+</td><td>2</td><td>100%</td>`）是正面范例。`coverage.py` 未安装，无量化覆盖率。
- **建议**：关键数值（bench 百分比、Rank IC、分桶胜率）尽量断言具体数值；引入 `coverage.py` 设最低行覆盖门禁（至少对 `aitrader/` 核心模块）。

#### P2-2 实时行情负向分支未测
- **现象**：`_fetch_realtime` 只测成功解析（v08）与重试（v17）；`close<=0`、字段 `<32`、空文本、非"今日"返回 `None` 等负向分支未测；`_ipv4_first_getaddrinfo` 未测。
- **影响**：真实行情异常形态（停牌/字段缺失）下 `_fetch_realtime` 的容错无保护。
- **建议**：补 `close<=0` / 空文本 / 字段不足 → 返回 `None` 的用例。

## 3. 做得好的地方

1. **历史真 bug 全部有针对性回归测试且 dtype 修复到位**：政策 `date==str`（v22 用真实 `date` 对象 + `wrong_date` 反向用例）、回撤告警永不触发（v19 全量快照触发/单元素不触发/`_maybe_notify` 集成 3 条）、force 重复成交（v20 唯一约束幂等 + 迁移去重）、计息双计（v17 `force` 重跑不双计）——"先修 bug 再补测试"闭环完整，且 v22 正是对"mock 与真实不一致"的纠正。
2. **负向/边界用例意识强**：`rank_ic` 常数/空/长度不等、`compute_metrics` 空/纯亏损、`_fair_pnl` 单快照除零、`attribute_trades` 未平仓忽略、政策 `wrong_date` 返回空、`before_close`/`calendar_unavailable` 守卫等都有覆盖，不是清一色 happy path。
3. **网络全部 mock 且确定性强**：行情走 `FakeDataSource`/`FakeHttp`、日报 mock `fetch_daily_bars`，无真实网络依赖；16.6s 全过、可重复；新浪实时样本（v08 32 字段）与政策 dtype（v22）贴近真实结构，说明"mock 需贴近真实"的原则已被贯彻到多数关键接口。

## 4. 一句话总结

197 个测试把"每日批处理 + 回测"核心链路守得很扎实、历史 bug 也都有回归护栏，但最大的洞是 **CLI 入口从未被端到端跑过、reporter 绘图与真实数据源复权/日历路径没测、P0-4 崩溃写中途缺回归**——而这三点正是无人值守"自动 Agent"最容易翻车的地方，建议按 P0-1 → P0-2 → P1-1/P1-2 顺序补齐。
