## 1. 结论摘要

1. **政策注入"接了线却没真正生效"**：08-08 前受 `date==str` bug 影响 `policy_text` 恒空（prompt 无政策段）；08-10 修复后政策段已注入（08-13 占 prompt 61%），但内容以**海外宏观噪音为主**（澳/印/日/韩新闻被宽松关键词命中），且模型**从未输出过 `[政策]` 标签**——除了 bug，还有两个叠加原因：reason 标签契约被 JSON 示例自相矛盾地破坏（buy 全部无标签），以及政策文本"标题｜内容"结构残缺/重复、缺时间戳与持仓归因（正是 PP-7 未落地的现象）。
2. **置信度链路在真实盘"空转"**：历史 AI buy 的 `confidence` 全为 NULL（旧代码未存）+ 当前仅 buy 才存（hold/sell 丢弃）+ `min_confidence_buy=0`（门槛关闭）+ Rank IC≈0（confidence 无预测信息）——confidence 在真实盘既不参与门控、样本也撑不起校准，属"记录但不使用"。
3. **决策系统性保守（只买不卖）**：历史 47 条 AI 决策 **0 条 sell**、buy 仅 4 条（集中在 08-07/08-08 两天），此后 6 天全 hold；叠加止损/止盈默认关闭 → 持仓一旦买入便"永不止盈止损、只由模型 hold"。样本小但模式与回测诊断（hold 占 93%、"AI 太保守"）一致。

## 2. 问题清单

### 🔴 P0

#### P0-1 政策注入=海外噪音 + 模型从不使用 `[政策]` 标签（重点核实项）
- **现象**：ai_policy 引擎历史上从未产出 `[政策]` reason；08-10 起 prompt 明明有政策段（623~1386 字符），模型仍只回 `[趋势]/[其他]` 或空标签的 hold/buy；且注入内容与 A 股持仓无关。
- **证据**：
  - 备份库 `decisions`：ai/ai_policy 各 2 条 buy、reason 全无标签；hold 仅 `[趋势]`/`[其他]`；全表 `reason LIKE '%政策%'` = **0 条**；`raw_output LIKE '%政策%'` = 0 条。
  - `prompt_json` 留痕：`2026-08-08` 无政策段（704/792 字符，`date==str` bug 把当天政策滤空）；`08-10/11/12/13` 有政策段，08-13 政策段 **1386/2278 字符（占 61%）**。
  - 08-13 政策段原文：首条 `｜财联社8月13日电，澳大利亚国民银行…`（**标题为空**→裸"｜内容"）；其余为印度反倾销/日本物价/韩国税收等**海外新闻**——被关键词 `利率/货币政策/财政/央行` 误命中（`config.py:PolicyConfig.keywords` 无"中国/国内"限定）。
  - 数据链路：`datasource.py:306-308` 直接 `f"{title}｜{content}"` 整段塞入、无时间戳、无长度截断、无去重；`datasource.py:308` 关键词过滤命中海外新闻。
- **影响**：政策版每天多付约一半 prompt token 换回"正确忽略的噪音"；`[政策]` 归因维度永远为空 → 政策增量无法统计；若未来出现真正影响 A 股的盘中政策，无时间戳/无持仓映射的裸文本既有"利好出尽/预期差"误判风险，也会因"噪音太多"被一并忽略（PP-7 明示的"政策→标的/板块映射缺失"）。
- **修复建议**：落地 PP-7（`policy_archive` 落库 + 结构化单行 `[09:35|央行|降准0.5pp|摘要]` + "与持仓无关则忽略" + 回测回放 A/B）；关键词加"中国/央行/证监会/国常会"等国内限定或按交易所相关度过滤海外新闻；标题为空跳过、标题/内容去重并限长（每条 ≤150 字符）；在积累足够政策样本前，按 PP-7 判定标准（ai_policy 样本外 Sharpe ≥ ai+0.1）再决定是否保留政策版，否则如实降级。

### 🟡 P1

#### P1-1 reason 标签契约被 JSON 示例自相矛盾（buy 全部无标签的根因）
- **现象**：`_build_prompt` 规则 6 要求 `reason` 以 `[趋势]/[回调]/[政策]/…` 开头，但同段 JSON 示例的 reason 是 `"一句话理由"`（**无标签**）→ 模型模仿示例输出，buy 全无标签；hold 从 08-11 起才有 `[趋势]/[其他]`。
- **证据**：`deepseek.py:_build_prompt`（示例行 `"confidence":0.7,"reason":"一句话理由"` 与规则 6 标签枚举并存）；备份库 ai buy reason `"沪深300ETF近期企稳，小幅反弹，估值合理，谨慎建仓。"` 无标签；`attribution.parse_tag` 会把此类 buy 全部归入"其他"。
- **影响**：归因复盘把 AI 买入全部计为"其他"，"哪类理由赚钱/政策理由是否有效"无法统计——`[政策]` 标签从未出现的另一部分原因正在于此（模型即便看到了政策也不会按契约打标签）；N-5 的归因闭环在真实盘失效。
- **修复建议**：示例改为 `"[趋势] 放量突破20日线"` 带标签；system 与 user 双处强调"buy 必须带标签"；或在 `_parse` 后对缺失标签的 buy reason 补 `[其他]`（保留原始 reason 留痕），保证归因可用。

#### P1-2 confidence 真实盘空转：无门控、无样本、无惩罚
- **现象**：历史 AI buy 的 confidence 全为 NULL；`min_confidence_buy=0` 关闭门槛；真实盘 forward_return 回填 = 0 条 → Rank IC/信心分桶长期无样本。
- **证据**：备份库 `confidence` 统计（ai/ai_policy buy 各 2 条，`SUM(confidence IS NULL)=2`，非空=0）；`forward_return IS NOT NULL` 全为 0（20 日窗口未满 + 样本极少）；`config.json` risk 块无 `min_confidence_buy` → `config.py:35` 默认 0 关闭；`database.py:312` **只对 buy 存 confidence**（hold/sell 丢弃）；`docs/PREDICTION_IMPROVEMENTS.md`：Rank IC 全部≈0、confidence 集中 0.6~0.7 窄区间。
- **影响**：低信心买入照常成交（门槛关）、"高信心但错"无任何惩罚/校准反馈；信心分桶日报表在真实盘长期空转；confidence 沦为"记录但不用"的装饰字段。
- **修复建议**：① 若要启用，在 config risk 设 `min_confidence_buy`（如 0.6）真实盘积累样本再评估；② `add_decision` 改为对 hold/sell 也存 confidence（扩大校准样本，成本≈0）；③ 对"高信心且 forward_return 大幅为负"的错单加事后回填标注，可在 feedback_n 复盘节中提示模型"高信心错单"警示。

#### P1-3 政策文本质量：结构残缺 / 重复 / 超长（PP-7 未落地的直接后果）
- **现象**：`标题｜内容` 结构出现空标题（`｜财联社8月13日电…`）、标题与内容高度重复（商务部反倾销条目标题≈【】内内容）、单条内容超长（韩国税收一条 300+ 字符）；08-13 政策段 1386 字符占 prompt 61%。
- **证据**：08-13 ai_policy `prompt_json` 政策段原文；`datasource.py:306-308` 拼接逻辑（无 `str()` 空值保护、无截断）。GBK 乱码**未现**（缓存 2000 条异常字符=0，编码正常）——乱码怀疑不成立，但长文拼接过期/超 token 风险仍在。
- **影响**：token 浪费 + 噪音稀释真实信号 + LLM 可读性差；政策段越长，模型越可能"忽略整段"，政策注入价值趋近于零。
- **修复建议**：每条取"标题（去重）＋内容前 100~150 字符"，空标题跳过；或直接落地 PP-7 结构化单行格式（含时间戳/命中关键词/摘要）。

#### P1-4 决策系统性保守：只买不卖 + 长期 hold
- **现象**：历史 AI 决策 0 sell；AI buy 集中 08-07/08-08，此后（08-09~08-13）两引擎全 hold；rule 3 buy 0 sell。
- **证据**：备份库 action 分布（ai hold 22 / buy 2、ai_policy hold 21 / buy 2、rule buy 3，**sell 全表 0**）；`trades` 7 条全 buy；08-07/08-08 建仓后 6 天无任何减仓；`docs/PREDICTION_IMPROVEMENTS.md`：回测诊断 hold 占 93%、"AI 基线太保守（1 年 12 笔，跑输买入持有）"。
- **影响**：无止损/止盈（`config.json` risk 无 stop_loss/take_profit，`RiskConfig` 默认 0 关闭）+ 模型不 sell → 单边下跌死扛、浮盈永不止盈；真实盘账户已表现出"买入即长期持仓"。
- **修复建议**：先积累真实盘样本验证是否真为系统性偏向；评估对 AI 单独做止损/止盈网格（PP-5 结论仅对 rule 有效，AI 需单独 A/B）；提示词给 sell 提供与 buy 对称的示例与触发条件（如"破位/达到目标/风险释放时主动减仓"），弱化"宁缺毋滥"对卖出纪律的压制。

### 🟢 P2

#### P2-1 反馈循环（`_closed_trades`）潜在过拟合——当前关闭，风险潜伏
- **现象**：`feedback_n=0`（config 未配、默认 0）→ `_closed_trades` 恒空、prompt 无复盘节；PP-6 A/B 显示开启后成交 4→11、换手 1.75 偏高、收益略降。
- **证据**：`config.json` 无 `feedback_n`；`config.py` `Settings.feedback_n` 默认 0；`batch.py:132-140` 空返回；`docs` PP-6 A/B（11 笔、样本少）。
- **影响**：若开启，近 N 笔盈亏反馈可能诱导"追涨杀跌"（模仿最近赚钱的买入理由重复犯错），且每日新平仓 → prompt 变化 → 缓存复用率下降（成本↑）；当前关闭无即时风险。
- **修复建议**：保持默认关；若开启，只给"净亏损/重复模式"警示而非全量明细，`feedback_n≤5`，并监控换手率与归因胜率变化。

#### P2-2 缓存复用在真实盘近乎无效（设计正确，非缺陷）
- **现象**：真实盘每天固定 2 次 API 调用、0 缓存命中；缓存 2000 键全部唯一。
- **证据**：`last_run.json`（08-13）`api_stats: ai calls=1/hits=0、ai_policy calls=1/hits=0`；`ai_response_cache.json` 唯一键 2000、重复 0；缓存键 `md5(model|temperature|system|prompt)`（`deepseek.py:_call`）已含 feature/market/policy/feedback 全部开关（随 prompt 变化天然进键，无串缓存正确性风险）。
- **影响**：缓存主要惠及回测与 `--force` 重跑；日常成本=每天 2 次调用，符合预期；无正确性风险。
- **修复建议**：无需修复；可留意政策段同日重跑内容不稳定导致命中率低（收益有限，可不做）。

## 3. 做得好的地方

1. **前视防护扎实**：政策按"发布日期==决策日 + 发布时间≤15:30"双重过滤（`datasource.py:291-299`，`date==str` bug 已修）；行情按决策日硬校验剔除陈旧标的（`batch.py:2.1` F-1/F-2）；快照记 `bar_date`、`source` real/replay 隔离；特征/市况/成交全部以决策日收盘为一致口径（decide-after-close, fill-at-close），未发现错位或未来信息。
2. **缓存键设计正确且自文档化**：`md5(model|temperature|system|prompt)` 天然涵盖全部注入开关，改 system/温度不会误用旧缓存；`api_calls/cache_hits` 记账让成本漂移可察觉；`prompt_json/raw_output_json` 全量留痕，使本次诊断能直接回放历史 prompt（正是证据来源）。
3. **降级与容错路径完备**：政策源异常→空文本优雅退化（`batch.py:_fetch_policy`）；模型异常→空仓 hold 降级并留痕（`batch.py` fallback）；单条解析失败不拖垮整批（`deepseek.py:_parse`）；`already_holding`/`too_many_buy` 等语义校验防止重复买同一标的（`deepseek.py:_validate` + `portfolio.py:validate_buy` 双保险），未发现同日重复建仓。

---

## 4. 一句话总结

提示词工程骨架（三段式 system、前视防护、缓存键、留痕）扎实，但**政策注入目前是"高成本噪音"、reason 标签契约被示例自相矛盾、confidence 在真实盘空转、决策偏保守不卖出**——四者共同导致"AI 决策质量闭环"在真实盘尚未真正转起来，建议按 PP-7（政策结构化+回测 A/B）→ P1-1（标签示例修正）→ P1-2（confidence 门控+全 action 存样本）的优先级推进。
