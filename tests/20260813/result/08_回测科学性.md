# 体检方向 08：回测科学性与口径（诊断结果）

- 评审对象：`ai_trader/`（回测 `aitrader/backtest.py`、报表 `aitrader/reporter.py`、入口 `run.py --bt`、数据源 `aitrader/datasource.py`、账本 `aitrader/database.py`）
- 评审日期：2026-08-13
- 方式：**只读**逐行核实真实代码 + 只读查询 `data/backtest.db` / `data/aitrader.db` / 备份库 + 内存库 FakeDataSource 只读回测实证（未写任何正式库）

---

## 1. 结论摘要

1. **P0-2 口径漂移仍然存在，且比文档描述的更严重**：回测默认 `adjust=hfq`（后复权，实证 510300 价差 **+18.6%**）+ `fill_mode=next_open` + 逐日计息；真实盘用**原始价收盘价**成交/估值 + config 未暴露滑点/止损/置信度门槛 + 计息从未生效（`last_interest_date` 全 NULL）。回测在分红/除权口径上**系统性高估**（hfq 隐含分红再投），真实盘在除权日**低估**（无分红到账模拟）——"真实盘表现不应优于回测"这一论断**只对成交假设成立，对复权口径不成立（方向相反）**。
2. **无前视偏差，P0-5（Rank IC 只收实际成交 buy）已真正修复**：回测逐日只喂"截至当日"行情、`policy_text=""`、`end_date` 过滤；内存回测实证被风控拒绝/重复买入的 buy **不进入成交、不进入 Rank IC**。日历守卫（P1-11）、回测 run ledger（P1-1）确实仍未做。
3. **ai_policy 回测退化为纯价格版已如实标注**（warning + 缓存共享，结果≡ai、不重复计费），但本质是"政策价值不可回测"（P1-5 政策归档未做），回测无法给出政策信息增益。

---

## 2. 问题清单

### P0（真口径缺陷 / 数据可信度）

#### P0-A 【口径漂移·复权】回测 hfq 估值/成交，真实盘原始价估值/成交——两者绝对口径差 18.6%
- **现象**：回测全链路用后复权价（估值 `prices=bars[-1].close` 是 hfq 后的 close，成交 `fill_prices` 也是 hfq 后的 next_open）；真实盘 `batch._run_engine` 用 `bars_map` **原始价**估值与成交（N-1 双 bars 方案：复权只用于特征，估值/成交/价格展示用原始价）。
- **证据**：
  - 回测：`backtest.py::Backtester` 用 `self.adjust`（`run.py:323` 传 `args.adjust or settings.adjust`）；`config.json` 为 `"adjust":"hfq"`、`"fill_mode":"next_open"`。
  - 真实盘：`batch.py::_run_engine` `prices={sym: bars[-1].close}` 取 `bars_map`（原始），`execute_decisions` 无 `fill_prices` → 成交价=当日收盘原始价。
  - 实测数据（`data/aitrader.db` bars + `adjfactor`，510300）：原始最近收盘 **4.729** vs hfq 收盘 **5.609**（累计分红 0.88/份，**+18.6%**）；除权日 2026-07-17 原始价跳空 **-3.45%**，hfq 仅 **-2.91%**（被平滑）。
- **影响**：同一资金在回测里按 hfq 高价买入 → 股数更少、现金占用不同 → 持仓市值/净值/换手/现金生息基数全部与实盘不可比；除权日回测平滑、实盘跳空且**无分红到账模拟** → 分红标的回测收益系统性高于实盘。长区间、分红多时偏差放大。
- **修复建议**：① 回测默认提供 `adjust=none` 基线（与实盘原始价对齐），`hfq` 只作为"分红再投"敏感度口径，报表同时给两条曲线；② 真实盘补"除权日分红现金到账"（复用 `adjfactor` 的 dividends，`cash += 每股分红×持股数`），消除除权日估值失真；③ 落地 `--print-config`（A-2）一键核对两套环境的 fill/adjust/计息口径；④ README 明确标注"回测 hfq≈分红再投口径，实盘为原始价+待补分红到账"。

#### P0-B 【口径漂移·计息】回测逐日计息，真实盘计息从未生效（交叉印证 IMPROVEMENTS P0-5）
- **现象**：回测每日 `apply_cash_interest`（`backtest.py:351`）；真实盘 `batch.py:292-298` 有条件计息，但真实库从未写入。
- **证据**：`data/aitrader.db` 与备份库 `account_states.last_interest_date` **三账户全部 NULL**；`daily_snapshots.interest` 全 0；v0.16 计息代码（08-12 16:02 合入）晚于真实库最后一批快照（08-12 15:30 部署版写入）。
- **影响**：真实盘空仓期货基利息漏计（配置 `cash_interest_rate=0.017`），净值曲线系统性偏低；而回测含利息 → 两边净值不可比（叠加 P0-A）。
- **修复建议**：按 IMPROVEMENTS P0-5 做 `last_interest_date IS NULL` 一次性回填 + `--health` 计息新鲜度检查；回测与实盘统一"是否计息"的开关。

### P1（可靠性 / 评测科学性）

#### P1-A 【日历守卫 P1-11 未做】`--end` 无交易日历守卫，节假日可被当"最近已收盘日"，且 end 被裁剪时静默
- **现象**：`_last_closed_trading_day` 仅 `while not ds.is_trading_day(d): d-=1`，**无 `calendar_ok` 检查**；`Backtester.run` 对 `end` 裁剪到实际有行情日时**不打印任何提示**。
- **证据**：`run.py:200-208`（`_last_closed_trading_day`，`calendar_ok` 未引用）、`run.py:298`（`end = args.end if args.end else _last_closed_trading_day()`）、`datasource.py:158-163`（`is_trading_day` 日历失败降级为"仅跳周末"，工作日一律交易日）、`backtest.py:263-266`（`dates` 过滤后无裁剪告警）。对照：批处理有 `calendar_ok=False` 保守跳过守卫（`batch.py:67`）。
- **影响**：① 默认 end 在日历不可用时可能落在节假日（与批处理口径不一致）；② 用户显式 `--end <节假日>` 时回测静默以节假日前最后交易日结束，区间边界与用户预期不符且无提示。
- **修复建议**：`_last_closed_trading_day` 检查 `ds.calendar_ok`，不可用则告警并回退昨天/要求显式 `--end`；`Backtester` 当 `dates[-1] < end` 时打印"end 被裁剪至 YYYY-MM-DD（非交易日/无行情）"。

#### P1-B 【run ledger P1-1 未做】回测无结构化留档，历史实验不可追溯/不可对比
- **现象**：每次回测只打印 + 生成 HTML；配置、指标、基准、Rank IC、API 调用量**均不落库**；无 `backtest_runs` 表、无 `--list-runs`。
- **证据**：只读查询 `data/backtest.db` schema **无 `backtest_runs` 表**（仅有 accounts/bars/decisions/trades/snapshots/batch_runs）；`run.py::run_backtest` 末尾只 `print` + `plot_backtest_curves` + `build_backtest_report`；`Backtester.run` 每次 `reset_account`（`backtest.py:278`）→ 上次回测指标被覆盖，仅剩流水。
- **影响**：跑过的实验（fill/adjust/滑点/止损/温度/模型 A/B）无法历史对比，"自我改进燃料"缺失（A-1 前置）。
- **修复建议**：新增 `backtest_runs` 表（run_id/时间/区间/config 快照/各引擎 metrics/bench/rank_ic/api_calls/cache_hits/fill/adjust/feature/market_env），每次回测写入；`--list-runs` / `--diff-runs A B`；回测落库决策顺带回填 `execution_result`（见 P2-A）。

#### P1-C 【日报基准 P1-10】日报基准实时联网 + 未复权 + 500 根硬编码 + 失败静默
- **现象**：`build_daily_report` 每次联网拉新浪 500 根日线算买入持有，`except: bench_line=""` 静默留空。
- **证据**：`reporter.py:253-275`（`ds.fetch_daily_bars(first_sym, 500, ...)` 后按 `first_date` 过滤、`bench_ret = bars[-1].close/bars[0].close - 1`）。
- **影响**：① 账户运行超约 2 年后 `first_date` 早于 500 根窗口 → 基准区间被截断；② 数据源/代理故障时基准静默消失，用户无从分辨"没基准"还是"拉取失败"；③ 缺佣金与货基利息，与策略累计盈亏口径不完全一致（注意：日报策略估值本就是原始价，故"未复权"这一点与回测 hfq 不同、但与日报自身口径一致——需按此精确归因，勿把 hfq 问题重复计入）。
- **修复建议**：基准改本地 `bars` 表 + `compute_benchmark`（含佣金、不联网）；失败时打印"基准获取失败（原因）"；窗口按 `first_date` 动态计算。

### P2（工程体验 / 留痕完整性）

#### P2-A 【回测留痕缺失】回测 `--record-decisions` 落库的决策 `execution_result` 全为 NULL
- **现象**：回测路径 `execute_decisions` 返回的 `execution_results` 没有写回决策表（真实盘 `batch.py:357-361` 有 `update_decision_execution`，回测 `backtest.py` 没有）。
- **证据**：`data/backtest.db` 的 ai 账户 **830 条 decisions 全部 `execution_result=NULL`**；内存库 FakeDataSource 回测实证 decisions 亦全 NULL（成交、被拒、重复买入无法从库中区分）。
- **影响**：回测留痕无法从库中还原"哪些 buy 成交/被拒/无效"，可追溯性与真实盘不对等（与 P1-B 叠加削弱回测台账价值）。
- **修复建议**：回测 `execute_decisions` 后按 `execution_results` 调 `update_decision_execution` 回填（与 batch 共用同一路径）。

#### P2-B 【IC 校准边界】真实盘 `get_uncalibrated_buys` 的 `execution_result IS NULL` 分支会纳入"结果未记录"的历史 buy
- **现象**：`database.py:330-336` 条件为 `(execution_result IS NULL OR execution_result LIKE 'executed:buy%')`；NULL 分支无法区分"历史确成交但当时未记录"与"被风控拒绝但未记录"。
- **证据**：备份库（重置前）有 **4 条 buy 决策 `execution_result=NULL`**（v0.10 之前无该列的历史遗留）；当前库 `forward_return` 全 0（20 日窗口未满，尚未回填，未发生污染）。
- **影响**：一旦窗口满 20 日，这些 NULL buy 可能被当作"有效成交"计入真实盘 Rank IC，引入被拒样本 → IC 失真。
- **修复建议**：迁移时对历史 buy 决策显式标记（成交/被拒/未知），校准只认 `executed:buy`；或对 NULL 一律不纳入并告警。

#### P2-C 【停牌处理不一致】回测无"决策日无 bar 剔除"硬校验（真实盘有 stale_bars 剔除）
- **现象**：真实盘 `batch.py:80-92` 对最新 bar ≠ 决策日的标的**剔除不参与交易**；回测 `backtest.py:339-345` 对决策日无 bar 的标的沿用停牌前最后收盘价估值/决策，无剔除、无提示。
- **影响**：停牌标的在回测中以陈旧价参与决策与估值，与实盘口径不一致（市场正常时影响小，停牌/极端日会放大）。
- **修复建议**：回测对决策日无 bar 的标的采用与 batch 相同的陈旧剔除逻辑（或至少打印告警）。

#### P2-D 【政策版回测语义】ai_policy 回测退化已标注，但"政策价值"不可回测（P1-5 前置缺失）
- **现象**：`select_backtest_engines`（`run.py:142-155`）默认跳过 ai_policy 并 warning："回测默认跳过 AI·政策版…如确需回测请用 --engine ai_policy（退化为纯价格版）"；`DeepSeekEngine._build_prompt` 在 `policy_text=""` 时无政策节，且 `_system_prompt` 不区分 include_policy → ai 与 ai_policy 回测 prompt 相同、缓存共享。
- **证据**：`deepseek.py:186`（`if self.include_policy and ctx.policy_text:`）、`deepseek.py:76-90`（system 不含政策）、`deepseek.py:96-97`（注释"ai 与 ai_policy 提示词相同时共享缓存"）；`data/backtest.db` ai_policy 账户仅 3 快照/2 成交（曾误跑一次短回测）。
- **影响**：回测无法回答"政策信息对决策是否有价值"（P1-5 政策未归档 → 无法按日期回放），`--engine ai_policy` 得到的是与 ai 完全重合的曲线，用户易误读为"测过政策"。
- **修复建议**：① 报表对 ai_policy 曲线附注"未验证政策价值（无历史政策源）"；② 落地 P1-5 `policy_archive` 后，`Backtester` 按日期回放 ≤ 决策日 15:30 的历史政策做真回测。

## 3. 做得好的地方

1. **前视防护完整且成体系**：回测逐日只喂"截至当日"行情（`bisect_right` 切片，`backtest.py:339`）、`policy_text=""` 不注入当下政策（`backtest.py:359`）、`end_date` 过滤、`compute_forward_returns` 用**决策日收盘**作 entry（`backtest.py:188-215`，无未来数据）；真实盘侧有 bar_date 硬校验 / 政策 15:30 截断 / 收盘守卫。
2. **P0-5 已真正修复并被实证**：回测 buys 只收实际成交（`exec_buys` 过滤，`backtest.py:395-397`）、真实盘校准只认 `executed:buy`（`database.py:330-336`）；内存库 FakeDataSource 回测实证：不足 1 手被拒 / 重复买入被拒的 buy **均不进入 trades、不进入 Rank IC**（n=1 仅含真实成交）。
3. **回测报表的基准与策略同起点、同复权、同佣金**：`run.py:340-345` 用 `adjust=args.adjust or settings.adjust` 拉基准（与策略 hfq 同口径），`compute_benchmark` 扣单边佣金（PP-1），`plot_backtest_curves`（`reporter.py:314-385`）策略净值与基准都从 1 归一 + 回撤面板——回测侧基准对齐扎实（与 P1-10 的日报基准形成鲜明对比）。
4. **ai_policy 回测退化如实标注且不重复计费**：warning 明确"退化为纯价格版，结果与 ai 引擎一致"，缓存共享避免双倍烧 API。

---

## 4. 一句话总结

回测在"**无前视、Rank IC 只收实际成交、基准同起点同复权**"上做得扎实，但**估值/成交的复权口径（hfq vs 原始价，实测差 18.6%）与计息（回测有、实盘从未生效）导致回测与实盘不能直接对比**，叠加 `--end` 日历守卫与回测 run ledger 缺失，回测结论只能当"相对排序 / A-B 对比"看，不能当"实盘预期"看。
