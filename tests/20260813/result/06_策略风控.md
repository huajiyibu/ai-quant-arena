# 体检方向 06：策略与风控（诊断报告）

> 范围：只读诊断，未改任何代码/数据。证据含真实代码（文件:行号）与备份账本 `data/aitrader_backup_20260813_1630.db`（已重置，查历史用）。
> 日期：2026-08-13

## 一、结论摘要（3 条）

1. **P0-2 口径漂移属实**：`config.json` 的 `risk` 块只暴露 3 个字段，滑点/止损止盈/置信度门槛走 pydantic 默认值 0；且 `--stop-loss/--take-profit/--slippage/--min-confidence` 只作用于回测分支，**真实盘每日批处理只应用 `feature_inject`/`market_env`** → 真实盘恒无滑点、无止损失止盈、无置信度过滤，"改进点看得见但真实盘难对齐"。
2. **止损从未真正触发过**：备份账本 trades/decisions 中 `[stop_loss]/[take_profit]` 记录 = 0；rule 引擎"爆亏一千二"（-1217.61）实为 3 笔买入后约 -0.12% 的小额浮动回撤（佣金 -162.5 + 浮动 -1078.8），各持仓仅 -0.6%~+1.3%，**即便开启 8% 止损也不会触发**——"没有止损"不是其成因。
3. **执行/成本口径三引擎公平、风控机制本身健壮**：rule/ai/ai_policy 共用同一 `RiskConfig` + `execute_decisions`（佣金双边、滑点/止损/置信度机制均已接线）；`validate_buy` 现金 + 单笔 30% + 单日 50% + 整手兜底 → 无负现金/爆仓。缺的只是**配置暴露与批处理接线**。

## 二、问题清单

### P0

**P0-1 真实盘风控/成本参数悬空（P0-2 口径漂移）**
- **现象**：`config.json` risk 块仅 3 字段；`run.py::_run`（每日批处理）只应用 `args.feature_inject`/`args.market_env`（run.py:507,510），`--stop-loss/--take-profit/--slippage/--min-confidence` 仅在 `run_backtest` 生效（run.py:257-270）→ 用户在真实盘跑 `python run.py --stop-loss 0.08` 被**静默忽略**：不报错、不生效。
- **证据**：
  - `config.json`（真实文件）risk 块实际内容 = `max_position_pct/max_daily_buy_pct/commission_rate` 三字段；
  - `aitrader/config.py:35-38`：`min_confidence_buy/slippage_bps/stop_loss_pct/take_profit_pct` 默认全 0；
  - `run.py:257-270`（回测应用）vs `run.py:507-510`（批处理仅两参数）；
  - `docs/IMPROVEMENTS.md` P0-2 同款记录（v0.6 起列为存量未修）。
- **影响**：真实盘永远无止损保护（急跌只能死扛）、成交从不计滑点（成本被低估）、AI confidence 门槛恒关；A/B 得出的滑点/止损结论无法在真实盘复现。
- **修复建议**：① config.json risk 块补全 4 字段（显式写 0 或目标值）；② `_run` 批处理路径同样应用这 4 个 CLI 参数，或至少对"批处理模式下传入这些参数"给出 warning"仅回测生效"；③ 新增 `--print-config` 打印真实盘/回测各自实际生效参数（IMPROVEMENTS.md A-2）。

### P1

**P1-1 止损为"日收盘·基于成本价"，无盘中/trailing 监控**
- **现象**：`apply_stop_rules` 仅按决策日收盘价与**成本价**（`p.cost_price`）计算盈亏（现价≤成本×(1-止损)），非最高点回撤、无盘中监控；触发后真实盘按当日收盘成交、回测按 next_open+滑点。
- **证据**：`portfolio.py:84-101`（`pnl_pct = price / cost_price - 1`）；`batch.py:336`、`backtest.py:381`（均先 stop 后 execute）。
- **影响**：单日跳空破位会以更差价格成交（真实盘收盘成交偏乐观）；"涨到 8% 又回吐"捕捉不到。属日频策略的合理近似，但口径需文档化。
- **修复建议**：README 注明"日收盘止损、成本价基准、非 trailing"；可选让止损成交价也走 next_open 与回测对齐。

**P1-2 止损强制卖不进 decisions 账本（审计缺口）**
- **现象**：forced 止损决策被执行并生成 trades，但 batch 只把 `result.decisions` 写入 decisions 表，`execute_decisions` 收到的是 `forced + result.decisions` → 止损单只在 trades 可见、决策表无对应记录；`execution_results` 按 symbol 作 key，同 symbol 多决策后者覆盖前者，`update_decision_execution` 只回填 (account,date,symbol) 首个 NULL 行。
- **证据**：`batch.py:326-327`（只 add result.decisions）→ `batch.py:337`（execute forced + decisions）→ `batch.py:344`（回填）；`database.py:450-456`（`WHERE ... AND execution_result IS NULL`）。
- **影响**：一旦真实盘开启止损，止损事件无法在决策表/归因统计中呈现；同 symbol 同日多决策时执行结果串行覆盖。
- **修复建议**：forced 决策也 `add_decision`（或接受"trades.reason 带 `[stop_loss]` 标签"作折中）；`execution_results` 改用 (symbol, action) 复合 key。

**P1-3 rule 引擎参数硬编码 + 与 min_confidence 隐性耦合**
- **现象**：`RuleEngine(fast=5, slow=20)` 硬编码默认（`engines/rule.py:14-15`），config.json 无法调参；rule 的 `Decision.confidence` 恒为默认 0.5（`models.py:44`），一旦 config 开启 `min_confidence_buy>0.5` → rule 全部 buy 被 `risk_rejected:low_confidence` 拒绝 → rule 直接瘫痪。
- **证据**：`engines/rule.py:14-15`；`models.py:44`（`confidence: float = 0.5`）；`portfolio.py:151-153`（低信心拒绝）。
- **影响**：多引擎公平性在"置信度门槛"维度隐性耦合——给 AI 配门槛会误伤 rule；rule 也无法做窗口敏感性验证。
- **修复建议**：rule 窗口参数进 config（可选）；`min_confidence_buy>0` 时打印"rule 引擎会被全部过滤"提示。

### P2

**P2-1 滑点/成本建模简化，真实盘从未计滑点**
- **现象**：滑点固定 bps 买卖双边（buy 上浮/sell 下压，`portfolio.py:142-146`），无成交额依赖、无涨跌停不可成交、无最小佣金（A 股 5 元下限）；无印花税——但标的是 ETF 本无印花税，成本模型对 ETF 成立。真实盘 `slippage_bps=0` 从未计滑点。
- **证据**：`portfolio.py:142-146,180`；grep 无印花/tax 字段；config.json risk 无 slippage_bps。
- **影响**：真实盘成交成本被低估；小单（<2 万元）实际佣金有 5 元下限被忽略。
- **修复建议**：config 暴露 `slippage_bps` 后真实盘即生效（机制已接）；可选补 `min_commission`；ETF 无需印花税（如实即可）。

**P2-2 PP-5 止损网格结论适用范围窄**
- **现象**：12 组合（stop 0/5/8/12% × take 0/10/20%）× 仅 rule 引擎 × 2021-2024 震荡市，"夏普≥基线+0.1 且回撤降≥3pp"判定下无有效组合 → 保留无止损默认；AI 止损网格未跑（烧 API + 止损触发会分叉计费）。
- **证据**：`scripts/stop_grid.py`（`STOP_GRID`/`TAKE_GRID`）；`docs/PREDICTION_IMPROVEMENTS.md` PP-5 网格结论。
- **影响**："无有效组合"不能推广为"止损永远无用"，仅对 rule + 震荡市有效。
- **修复建议**：文档标注结论适用范围；AI 网格待历史数据积累后补；可拆"单笔止损 vs 账户级回撤熔断"分别评估。

**P2-3 历史 decisions 无执行结果回填（存量）**
- **现象**：备份账本 decisions 47 条中仅 rule 3 条 buy 有 `execution_result`，ai/ai_policy 的 buy（08-07/08-08 成交）为 NULL（v0.4 回填功能上线前）→ 风控拒绝统计在历史上缺失。
- **证据**：备份库 `decisions.execution_result` 分布 = `NULL 47 / executed:buy 3`；`database.py` 回填仅发生在执行当天。
- **影响**：无法从历史统计"被风控拒绝/截断"比例；对本轮体检影响小（账本已重置）。
- **修复建议**：如实记录"历史未回填"；重置后新账本从零开始回填。

## 三、做得好的地方

1. **多引擎公平性达标**：rule/ai/ai_policy 共用同一 `RiskConfig` + `execute_decisions`，佣金双边应用（buy 计入成本、sell 扣 proceed），`validate_buy` 现金 + 单笔 30% + 单日 50% + 整手向下取整兜底 → 无负现金/爆仓可能，对比的成本口径是公平的。
2. **止损/止盈机制设计合理**：成本价基准、先于模型决策执行、reason 带 `[stop_loss]/[take_profit]` 标签可归因、默认 0 关闭向后兼容；PP-5 网格实验诚实落地"无有效组合则保留默认"，没有为了"看起来有风控"而硬开。
3. **风控留痕机制已具备**：`execute_decisions` 返回 `(state, trades, execution_results)` 三元组 + `update_decision_execution` 回填（风控拒绝/价格缺失/截断可统计），Rank IC 只收实际成交 buy（P0-5）——机制健壮，缺的只是配置暴露。

## 四、一句话总结

风控与执行机制本身健壮且三引擎公平，但 `config.json` 的 risk 块只暴露 3 字段 + 批处理路径静默忽略风控 CLI 参数，导致真实盘恒无滑点/止损/置信度门槛——"爆亏一千二"的真相只是 0.12% 的浮动回撤，止损开了也不会触发，真正要修的是**把风控参数暴露并接线到真实盘**（P0-1）。
