# 体检方向 11：用户体验与文档（诊断结果）

> 评估对象：AI Quant Arena（`ai_trader/`）
> 视角：产品体验设计师 + 技术文档专家 —— "不懂金融的开发者第一次上手"
> 方法：只读核查 README / SRS / DESIGN / config / 日报产物 / CLI（运行 `--help`） / 辅助脚本
> 日期：2026-08-13

## 1. 结论摘要

1. **CLI 第一入口直接崩溃**：`python run.py --help` 抛 `ValueError: unsupported format character` traceback，新手连帮助都看不到（P0）。
2. **"小白友好"名不副实**：日报会渲染 `Rank IC` / 信心分桶 / 归因 / "起点归一" / `conf None` 等无解释的专业术语，且空账本（重置后）静默跳过、卡片区空白，无"暂无数据"提示（P1）。
3. **文档与代码多处脱节**：README 测试数（28）与 SRS（184）均与实际（197）不符；README 写了不存在的 `--health`；`--market-env` 默认值在 README / CLI help / config.json 三方互相矛盾（P1）。

## 2. 问题清单

### P0

**P0-1 · `python run.py --help` 崩溃，帮助信息无法查看**
- 现象：执行 `python run.py --help` 直接抛 `ValueError: unsupported format character '?' (0x5f3a) at index 21`，而不是输出参数帮助。
- 证据：`run.py:447` `help="止损阈值（0~0.5，如 0.08=跌8%强制卖出；默认0关，PP-5）"` 与 `run.py:453` `--take-profit` 的 `"涨20%强制卖出"` —— help 字符串含裸 `%`，argparse 会按 printf 格式化，遇 `%强` 无法解析而崩溃（实跑复现，退出码 1）。README 回测示例还推荐 `--stop-loss 0.08 --take-profit 0.2`，必然触雷。
- 影响：排障/探索第一入口被堵死；23+ 个参数无法通过 `--help` 获知含义；CLI 可用性（任务点 2）直接不达标。
- 修复建议：help 字符串中 `%` 改为 `%%`，或将表述改为"跌 8% 即卖出"（"跌8个百分点"）。改后必须回归验证 `--help` 与 `--stop-loss 0.08`。

### P1

**P1-1 · README / SRS 测试数与实际不符，版本未同步**
- 现象：文档宣称的用例数与代码现状不一致。
- 证据：`README.md:12` "28 个 pytest 用例覆盖"；`docs/SRS.md:7` "代码已迭代至 v0.18（184 用例全过）"；实测 `pytest --collect-only -q` = **197 tests**。SRS 验收标准还勾选"文档齐全且一致：本版 v1.3 已同步至 v0.18 代码现状"，但三项口径互不相同。
- 影响：文档一致性（任务点 6）被破坏；新手据此判断"系统可信度"会得到错误信号。
- 修复建议：统一以实测数为准更新 README 与 SRS（含验收标准），或改为动态引用。

**P1-2 · 空账本（重置后）日报静默跳过，卡片区空白无提示**
- 现象：重置/新环境无快照的账户，HTML 日报中不出现任何卡片；全部账户为空时，日报只剩标题 + 基准对照，看起来"像坏了"。
- 证据：`aitrader/reporter.py` `build_daily_report` 中 `if not snaps: continue`（直接跳过，不渲染卡片、无兜底提示）；对比 `build_summary`（CLI）有 `[name] 暂无数据` 分支。当前 `reports/daily_report.html` 为空账本前的旧版，正好验证"卡片消失"。
- 影响：任务点 4 "重置后空账本是否有明确提示" —— 回答为否；用户无法区分"没跑成功 / 没数据 / 系统问题"。
- 修复建议：空账户渲染"（暂无数据）"灰卡片；全空时正文显示"⚠️ 尚无交易数据，请先运行 `python run.py`"。

**P1-3 · 日报专业术语无解释、信息过载，违背"小白友好"**
- 现象：卡片堆叠五层信息（真实盈亏 / 对比口径 / IC / 归因 / 分桶），多处术语无任何解释。
- 证据：`reporter.py` 渲染 `AI 信心校准 Rank IC：+0.xxx（已校准 N 笔）`、`按信心分桶（正收益占比）`、`归因复盘（按买入理由标签，已平仓配对）`、`对比口径（自 2026-08-10 起点归一）`、`货基利息累计`、`今日决策：510300 hold 0元(conf None)`。SRS 有术语表，但 README（小白入口）与日报 HTML 均无术语解释 / tooltip / 脚注。产物 `reports/daily_report.html`（旧版）与 reporter.py 最新能力也不同步，印证产物滞后。
- 影响：任务点 3 "日报可读性 / 对比图起点归一" —— 不达标；"hold / conf None / Rank IC / 起点归一 / 货基利息" 对金融零基础者不可读，且真实盈亏（相对 100 万）与对比口径（自 8-10 起点归一）并存易混淆。
- 修复建议：① 卡片加"术语小字注释/折叠说明"（Rank IC=信心准不准、起点归一=从同一起点比曲线、货基利息=闲置现金利息）；② 主口径醒目、副口径弱化；③ 对比图标题/坐标轴下方加一句"起点归一=把每条曲线从同一天的资金起点拉平比较"。

**P1-4 · README 记载不存在的 `--health`，且未告知真正的排障入口**
- 现象：README 给出 `python run.py --health` 示例，但该参数未实现；新手照抄报 `unrecognized arguments`。
- 证据：`README.md:84` `python run.py --health  # （规划中）...`；`run.py` 的 argparse 全部 `add_argument` 中无 `--health`。同时，真正的自查工具 `scripts/check_daily.py`（快照时点/决策/持仓/成交留痕）、`data/last_run.json`（每次运行结果）、`data/logs/app.log`（轮转日志）在 README "怎么看结果/异常反馈" 章节完全未提及。
- 影响：任务点 5 "出问题时能否自助排查" —— 回答为否；用户被指向不存在的命令，而可用排障手段被隐藏。
- 修复建议：README 删除 `--health` 行（或实现后补上）；在"怎么看结果"新增"排障：`scripts\check_daily.py` + `data\last_run.json` + `data\logs\app.log`"小节。

**P1-5 · `--market-env`/`--feature-inject` 默认值三方矛盾，且 CLI 只能开不能关**
- 现象：真实盘实际开启的注入开关，README、CLI help、config.json 说法互相冲突。
- 证据：`config.json` 设 `feature_inject:true`、`market_env_inject:true`（真实盘默认开）；`run.py:461` help `"提示词注入市场环境（B-3，探索性，默认关）"`；`README.md` 回测参数注释 `"--market-env 市场环境（默认开，用 --market-env 仅回测对照）"` 自相矛盾。且两参数均为 `action="store_true"`，config.json 已为 true 时用户无法用 CLI 关闭。
- 影响：用户无法从文档得知真实盘实际生效的提示词注入状态；实验者想关闭（对照 A/B）无途径；文档一致性（任务点 6）再扣分。
- 修复建议：统一默认值口径（以 config.json 为准，README/CLI 同步"默认由 config.json 控制，当前为开"）；补充 `--no-market-env` 类取反开关或 `--print-config` 明示生效值。

### P2

**P2-1 · `config.example.json` 与 `config.json` 不同步**
- 现象：按 README 复制 example 会得到功能缩水的配置，且新字段无注释。
- 证据：`config.example.json` 缺 `feature_inject` / `market_env_inject` / `cash_interest_rate` / `fill_mode` / `adjust` / `notify` 等字段（对比 `config.json`）；`fill_mode`/`adjust` 仅影响回测，但对小白无任何说明。
- 影响：新手复制 example 后"特征注入/市场环境/货基利息/复权/通知"全部失效，与 README 宣传的默认体验不一致。
- 修复建议：example 与 config.json 对齐；对每个字段加一行中文注释，并标注"仅回测生效"。

**P2-2 · `--print-config` 缺失（A-2 证实）**
- 现象：无查看"最终生效配置"（默认值 + config.json 覆盖 + .env 合并）的手段。
- 证据：`run.py` argparse 无 `--print-config`；`aitrader/config.py` 仅 `load_settings()` 返回对象，无 CLI 暴露。配置错误只能翻源码。
- 影响：任务点 5 排障体验受限；尤其 `.env` 的 `api_key` 覆盖与否、`market_env` 实际取值无法核对。
- 修复建议：增加 `--print-config`（脱敏，不输出 api_key），与 P1-5 的默认值明示一起解决。

**P2-3 · `scripts/install_task.ps1` 硬编码本机路径与 Python**
- 现象：脚本和 README 示例把 Python 与项目路径写死。
- 证据：`install_task.ps1:8-9` `$pythonw = "C:\veighna_studio\pythonw.exe"`、`$script = "D:\下载的堆砌\...\run.py"`（含中文路径）；README 安装/运行示例同样硬编码 `C:\veighna_studio\python.exe`。schtasks 注册、启动项 lnk 均引用该路径。
- 影响：换机/换环境/路径变动即失败；新手报错后不知从何改起。
- 修复建议：改为自动探测（`Get-Command python` / `$PSScriptRoot` 相对定位），或文件头注释"请按本机实际路径修改"。

**P2-4 · `scripts/bench_metrics.py` 硬编码打印"结论"数字**
- 现象：一个"基准风险指标"脚本在末尾打印一句看似由数据算出的结论。
- 证据：`bench_metrics.py` 末行 `print("同期 AI+市场环境：+9.52% | 夏普 1.57 | 回撤 2.86%")` —— 写死的常量，非计算所得。
- 影响：对不懂金融的开发者构成误导（误以为是脚本实时对比结果），也与脚本职责不符。
- 修复建议：删除该行，或明确标注"来源：历史 A/B 实验记录，非本次计算"。

**P2-5 · 任务背景中的 `README_ENG.md` 不在项目内**
- 现象：`ai_trader/` 下不存在 `README_ENG.md`。
- 证据：全仓搜索仅 `d:\下载的堆砌\vnpy-4.4.0\README_ENG.md`（vn.py 仓库根，是 vn.py 的英文文档，与 AI Quant Arena 无关）。
- 影响：本项目无英文文档（若面向英语读者则为缺失）；至少说明任务资料里该引用与实际不符。
- 修复建议：确认是否需为 AI Quant Arena 补英文 README；若不需要，从资料清单移除该引用。

## 3. 做得好的地方

1. **零参数即可跑通 + 全程留痕**：`python run.py` 即可三引擎跑今日，`config.json` 提供完整默认值；`data/last_run.json`、`data/logs/app.log`、`scripts/check_daily.py` 组成排障三件套；README 的"安装→配置(可选)→手动跑→定时任务"4 步清晰、每步都有具体命令。
2. **CLI 输出与异常反馈较友好**：收盘汇总区分"非交易日已跳过"、"[告警]…当日跳过交易（数据完整性保护）"、"[engine] 该日已处理过，跳过（--force 可强制重跑）"；`--date` 有格式/未来日期校验并给出可读报错；批次内部对行情失败/陈旧/降级均落日志。
3. **README 结构与 SRS 术语表完整**：目录结构、快速开始、CLI、回测评估、政策参考、测试、"怎么看结果"、免责声明齐全；SRS 术语表（Rank IC/复权/货基利息/置信度）恰好是日报缺的那份"翻译"，只是没接到日报和 README 上。

## 4. 一句话总结

工程与留痕扎实，但"新手第一次上手"被打折在入口体验上：`--help` 直接崩溃、日报术语无解释且空账本静默空白，加上 README/配置/脚本多处过时与自相矛盾，需要一次面向"金融零基础读者"的文档与 CLI 收敛。
