# 体检方向 12：评测方法论与证据可信度（诊断结果）

> 角色：实验设计 / 统计方法学评审（只读，不改代码）
> 日期：2026-08-13｜对象：AI Quant Arena（三引擎并行仿真 + 回测 A/B 体系）
> 数据依据：重置前备份库 `data/aitrader_backup_20260813_1630.db`、`docs/IMPROVEMENTS.md`（v0.7）、`docs/PREDICTION_IMPROVEMENTS.md`、`git log`（含 `70a36a4`）、`run.py` / `batch.py` / `reporter.py` / `backtest.py` 真实磁盘代码。

---

## 1. 结论摘要（3 条）

1. **当前系统尚不能产出统计上可信的"AI 更赚 / 更稳"结论**：重置前真实盘仅 **6 个交易日、每引擎 2~3 笔成交**（rule 3 笔 / ai 2 笔 / ai_policy 2 笔），回测 A/B 最优档也仅 **4~20 笔**；而全工程唯一的"样本不足"门槛是回测打印里 Rank IC 的 `n<15` 文字提示，日报/对比图/汇总对"3 天样本宣布胜负"**没有任何门禁**。
2. **历史结论大多不可追溯、且部分已被污染**：`70a36a4` 的"AI 夏普 1.57 vs 基准 1.18"来自 v0.15 回测（n=7 笔，非真实盘），**未被政策 bug 直接污染**（回测默认跳过 ai_policy），但样本极小 + LLM 记忆局限 + system 一改即翻车（v0.14 改 system 后基线从 +21.7% 崩到 +13.4%）；"政策版表现"全部结论因 `date==str` bug（v0.22 修复）**整体无效**。
3. **评测闭环的三个地基均缺失**：无 run ledger（A-1/P1-1）、无"预测 vs 实际"评分卡（A-3）、无"结论前口径校验"门禁——bug 污染结论只能靠用户肉眼事后发现，结论无法自动重跑、对比与复现。

## 2. 问题清单

### 🔴 P0（不修则任何"结论"都不可信）

#### P0-1 无最小样本规则——3~5 天样本即可"宣布胜利"
- **现象**：日报卡片、文本汇总、对比图直接渲染累计盈亏与曲线，无样本量标注、无显著性检验、无置信区间；系统不区分"过程展示"与"结论发布"。
- **证据**：
  - `reporter.py::build_daily_report / build_summary / plot_compare`：零样本门槛，主卡片直接显示"累计盈亏 +X 元"；
  - 全库唯一门槛 = `run.py:367` `Rank IC: 样本不足 n={ric_n}（<15 不显著）`（仅回测打印、仅 Rank IC，且只是文字）；
  - 备份库真实样本：rule 6 快照/3 笔、ai 6 快照/2 笔、ai_policy 5 快照/2 笔；
  - `backtest.py::compute_metrics` 的夏普在 `len(rets)>=2` 即计算（2 个观测就能输出一个"夏普"）。
- **影响**：任何"AI 更赚/更稳"的展示在统计上都是噪音；用户（非金融背景）会把 6 天、2 笔的曲线当成结论。这正是本轮重置的直接诱因之一。
- **修复建议**：① 报表层加"证据水位线"：成交 <30 笔或观测 <60 个交易日时，显示"⚠️ 样本不足，仅过程展示，不得下结论"水印并降级指标展示；② 引入 bootstrap / 配对符号检验给出置信区间与 p 值；③ 在文档层面把"宣布结论"改为需 run ledger（P0-2）+ 样本门槛双满足。

#### P0-2 评测不可闭环、结论不可追溯——A-1（run ledger）未做
- **现象**：回测的配置、指标、基准、Rank IC、API 成本、污染状态**不落库**；无 `backtest_runs` 表、无 `--list-runs / --diff-runs`；A-1 自动对比循环与 A-3 评分卡未落地。
- **证据**：
  - `IMPROVEMENTS.md` P1-1"回测结果无结构化留档（run ledger）"**仍标记未修**；A-1/A-3 未做；
  - 真实库无 `backtest_runs` 表（备份库表清单确认）；
  - `70a36a4` 结论只能靠 git commit 追溯，且已被后续 `91bc8a6` 从 README 删除（结论仍在历史里、无版本标注）；
  - `scripts/bench_metrics.py` 仍**硬编码**打印"同期 AI+市场环境：+9.52% | 夏普 1.57 | 回撤 2.86%"。
- **影响**：无法自动验证"最优配置"在 system/区间/样本变化后是否仍成立；bug 污染结论无系统化检测手段；结论不可复现、不可自动对比。
- **修复建议**：落地 P1-1（`backtest_runs` 落库：run_id/时间/区间/config 快照/metrics/bench/rank_ic/api_stats）+ A-1（`--list-runs / --diff-runs` 自动对比）+ A-3（日报"预测 vs 实际"评分卡）；`bench_metrics.py` 去掉硬编码结论，改为纯计算 + 自动标注样本量。

#### P0-3 无"结论前口径校验"门禁——bug 污染结论是常态而非例外
- **现象**：系统能跑、能全量留痕，但没有任何机制在建结论前自动校验"政策确实注入了 / 快照无前视 / 缓存键未串味 / 决策确实被执行"；v0.22 政策 bug 持续一周无人发现，直到用户肉眼质问。
- **证据**：
  - `v0.22` 修复记录：`AkSharePolicySource.fetch_macro_news` 里 `df["发布日期"] == decision_date` 为 `date == str`，恒 False → 政策版从上线起从未收到政策，全部"政策版表现"结论无效；
  - 旧测试 `test_v09` 未抓出是因为测试传 `date` 对象（`date==date` 恰好匹配）；
  - 备份库真实盘 **buy 决策的 `execution_result` / `validation` / `forward_return` 全部为 NULL**（08-07/08-08 建仓早于 v0.4 回填功能，且从未重跑）→ "决策是否真执行、是否被风控拒"在重置前不可审计；
  - `IMPROVEMENTS.md` P1-5 政策不归档（无 `policy_archive`）仍未修 → 政策输入不可复现。
- **影响**：所有依赖"某引擎收到了某输入"的结论都有被静默污染的风险；未来同类 bug 仍会在用户发现前污染结论。
- **修复建议**：① 报告/汇总生成前做"口径自检"（政策注入条数、`bar_date` 时点、前视检查、execution_result 覆盖率），不通过则日报标注"本轮不可信"；② 落地 P1-5 `policy_archive` 使政策输入可复现、可回测；③ 重置后第一件事验证 `execution_result` 回填在真实盘真实生效（v0.4 已实现但从未跑过）。

### 🟡 P1（归因与结论可信度不足）

#### P1-1 三引擎"对比"非严格 A/B——归因隔离不彻底
- **现象**：共享变量控制得好（同标的、同数据源、同执行层、同初始资金 100 万、同佣金口径），但引擎间差异 ≠ 策略差异：**建仓时点、仓位分配、LLM 温度随机性**都混入。
- **证据**（备份库 trades）：ai 08-07 建仓（510300 5 万 + 588000 3 万）；ai_policy 08-08 建仓（各 5 万）；rule 08-10 才建仓（159915 20 万 + 510300 30 万 + 588000 15 万）→ 起点与仓位三引擎各不同；`v0.22` 记录自己承认"差异纯来自建仓时点/仓位"；ai 与 ai_policy 各自独立调 DeepSeek，`temperature` 未锁定为 0 → 同输入也可能不同输出。
- **影响**：即使政策 bug 修复，ai vs ai_policy 的差异也不能干净归因于"政策"；把胜负归因于"引擎策略"混淆了时点/仓位/运气。
- **修复建议**：① AI 引擎 `temperature=0`（或多次决策取期望）以压低随机性；② 统一各引擎首次建仓口径（如同一受控起点）；③ 归因结论从"引擎胜负"改为"同输入不同输入的受控实验"，并配 bootstrap 显著性。

#### P1-2 归一化起点（`FAIR_START_DATE=2026-08-10`）是手选自由参数——可翻转"谁赢"
- **现象**：`FAIR_START_DATE` 是硬编码常量，起点选择直接决定胜负；且"真实口径"与"公平口径"两个数字并存，用户看到的"赢"取决于看哪个口径。
- **证据**：
  - `reporter.py:13` `FAIR_START_DATE = "2026-08-10"`（v0.21 显式常量）；
  - 备份库快照：ai 08-10 归一基准 = 1,001,194.73 → 08-13 = 1,000,554.70 ⇒ **公平口径 -640 元（亏）**；而真实口径 = +554.70 元（赚）——**同一账户，两个口径符号相反**；
  - 起点取在 rule 首次建仓日（08-10），恰好是"对 AI 最不利、对规则最友好"的切法之一（AI 08-07/08-08 的浮盈全被剔除）。
- **影响**："剔除提前建仓"方向正确，但起点是自由参数 → 存在"选好看角度"的空间；结论对起点敏感却无敏感性分析。
- **修复建议**：① 起点改为数据驱动确定性规则（如"所有引擎首个 `bar_date` 非空估值日的最大值"），去掉手工常量；② 报告同时标注两口径并声明"结论对起点敏感"；③ 做多起点敏感性分析（起点 ±N 日，结论方向是否稳定）。

#### P1-3 单一指标误导——主字段"累计盈亏"最受起点/首笔建仓主导
- **现象**：日报主字段 = 真实累计盈亏（绝对金额），6 天/2 笔样本下被首笔建仓时点与仓位主导；夏普/胜率在 2~3 笔下也无统计意义。
- **证据**：`reporter.py` 卡片 `t_amt/t_pct`（真实累计盈亏，相对初始资金）；`compute_metrics` 夏普 `n>=2` 即输出；真实盘每引擎仅 2~3 笔。
- **影响**：用户看到"AI +554 元"觉得赢了，但这是 2 笔、6 天、被建仓时点决定的结果。
- **修复建议**：① 主结论指标改为"相对基准超额收益 + 最大回撤/夏普 + 样本量"三联；② 单指标一律标注样本量与置信区间；③ 累计盈亏仅作"过程展示"不作"结论"。

#### P1-4 过拟合与数据窥探——旋钮在历史回测上选优，LLM 存在"开卷考试"
- **现象**：feature / market_env / feedback / 止损等旋钮**全部在 2025-06~2026-08 同一段回测区间上选优**（market_env n=7 笔即开启、feedback n=11 笔标注可选、止损网格 12 组合），多重比较未做校正；且该区间可能被 LLM 记忆（`PREDICTION_IMPROVEMENTS.md` 已自警"开卷考试"）。
- **证据**：market_env 开启标准"夏普 ≥ 基线 +0.1"是拍脑袋阈值（n=7）；PP-5 止损网格留了 2025-01~2026-06 样本外，但**其余 A/B 均无样本外确认**；v0.14 改 system 后基线从 +21.7% 崩到 +13.4%（缓存全失效）证明"最优配置"对 system 极敏感。
- **影响**：回测选出的"最优配置"在真实盘可能不成立；A/B 在"测假设"与"碰运气"之间，后者偏多。
- **修复建议**：① 所有 A/B 强制"先注册假设 → 训练段选优 → 独立样本外确认"（PP-5 已示范，推广到全部）；② 多次比较做 Bonferroni 校正或先验挑选；③ 把"LLM 记忆局限"设为永久标注（回测绝对收益不可外推，仅相对 A/B 有效）；④ 以真实盘前向积累为最终验证（B-1 已铺）。

#### P1-5 `70a36a4`"AI 夏普 1.57 vs 基准 1.18"结论——小样本 + system 敏感，证据力不足
- **现象**：该结论来自 v0.15 回测（ai + 市场环境，**n=7 笔**，2025-06~2026-08，next_open），非真实盘；未被政策 bug 直接污染，但**证据力不足以支撑"AI 风险调整后更优"**。
- **证据**：`70a36a4`（README 段落 + `scripts/bench_metrics.py` 新增）明确写"AI+市场环境 +9.52% / 夏普 1.57 / 回撤 2.86%"与"基准 1.18 / 8.41%"；来源 `051bb45` v0.15 实验（n=7）；回测默认跳过 ai_policy（`select_backtest_engines`），故政策 bug 不影响此数；但 `91bc8a6` 已把该 README 段落删除，结论成"历史快照"。
- **影响**：若被当作"AI 风险调整后更优"的长期结论引用，属过度外推；`bench_metrics.py` 硬编码该行会持续传播。
- **修复建议**：`bench_metrics.py` 删除硬编码结论行，改为纯计算 + 自动标注样本量（n<30 输出"探索性观察"）；文档将该结论降级为"小样本探索性观察，需真实盘积累确认"。

### 🟢 P2（留痕与口径的工程短板）

#### P2-1 真实盘执行结果/前向收益留痕不完整
- **现象**：重置前真实盘 buy 决策 `execution_result`/`validation`/`forward_return` 全 NULL；Rank IC 校准数据缺失（前向 20 日窗口从未满）。
- **证据**：备份库 `decisions` 查询（08-07/08-08 两引擎 4 笔 buy 全 NULL）；`IMPROVEMENTS.md` P0-5 指出 v0.16 计息、v0.4 回填等代码"从未在真实盘运行"。
- **影响**：真实盘"决策是否真执行/被风控拒"不可审计；AI 校准闭环（B-1）在真实盘尚无一条有效样本。
- **修复建议**：重置后验证 `execution_result` 回填、`forward_return` 随 20 日窗口滚动回填真实生效；补 buy 决策唯一约束防重复留痕。

#### P2-2 真实盘留痕存在重复决策记录
- **现象**：备份库 ai 引擎 08-08 有 6 条重复 hold（每标的 3 组），ai_policy 08-08/08-10 亦有重复——`--date` 回放/`--force` 与真实批处理混写，虽然成交有幂等，但决策留痕重复。
- **证据**：备份库 `decisions` 查询（08-08 ai 每 symbol 3 条相同 hold；08-08 为周六，对应 v0.12 N-12 记录的"周六异常快照"成因）；`daily_snapshots.source` 已区分 real/replay，但 decisions 无 source 列。
- **影响**：决策级留痕不可作为唯一事实源；任何"决策次数/分布"统计会被重复记录污染。
- **修复建议**：`decisions` 加 `source` 列（与快照对齐）；回放/真实写入分离；重复留痕做去重（或统计时按 source 过滤）。

## 3. 做得好的地方（2~3 条）

1. **共享变量控制到位，A/B 骨架正确**：三引擎同标的、同数据源、同执行层、同初始资金、同佣金/滑点口径（回测与基准同口径、PP-1 三口径方向一致已验证稳健）——这是有效对照设计的基础。
2. **前视防护体系较完整**：`end_date` 过滤 + 逐日切片、`bar_date` 硬校验（非决策日剔除）、政策 15:30 截断 + 决策日过滤、real/replay `source` 隔离、`compute_forward_returns` 无前视——工程层把"数据时效污染"堵得较死。
3. **诚实标注意识在增强，且认错机制存在**：LLM 记忆局限警示、Rank IC `n<15` 标注、README 曾写"样本少置信度有限"、v0.22 主动承认政策 bug 并全量重置、把"真实口径"与"公平口径"分离展示避免符号翻转误导——说明团队在"不让结论跑在证据前面"上是认真的，缺的是**把这种意识固化成机制**。

---

## 4. 一句话总结

**当前系统尚不能产出统计上可信的"AI 更赚/更稳"结论**（真实盘样本仅 6 天/个位数成交，无最小样本门禁、无 run ledger、无结论前口径校验）；但在工程地基（前视防护、留痕、多 AI 评审、重置后的干净账本）就绪的前提下，**预计真实盘积累约 3~6 个月（数十个交易日、百笔级成交）**，并补上 A-1 run ledger / A-3 评分卡 / 口径自检门禁与 bootstrap 显著性之后，才能以"相对基准超额 + 风险调整 + 置信区间"口径产出可信结论——**到那时 AI 模拟盈利才能对"实盘可行性"给出一个必要但非充分的正向证据**。
