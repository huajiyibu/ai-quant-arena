# 体检方向 03：数据管道可靠性 —— 诊断结果

> 角色：行情数据管道 / 数据工程专家
> 范围：`aitrader/datasource.py`、`aitrader/batch.py`、`aitrader/adjfactor.py`、`aitrader/util.py`、`run.py`、`aitrader/reporter.py`、`aitrader/database.py`
> 证据：代码逐行 + `data/logs/app.log` 真实日志 + `data/aitrader.db`（bars 表）实查
> 性质：只读诊断，未改任何代码

---

## 1. 结论摘要（3 条）

1. **正常路径 + 失败路径都有较完整防护**：socket 级硬超时、IPv6 过滤、`retry_call` 指数退避、交易日历降级守卫、实时补全 + "bars 最新日==决策日"硬新鲜度校验、政策去滞后（F-6）/去前视（F-7）、复权双 bars（N-1），历史遗留 P0 级缺陷（政策 `date==str`、前视、静默旧价）均已修复并有日志佐证（今日 bars 表 `max_date=2026-08-13` 说明实时补全真实生效）。
2. **仍有 3 个真实"单点/口径"缺口（均有日志/代码实证）**：① 行情只依赖新浪单一源（DNS/接口故障→整日剔除）；② 系统代理 `127.0.0.1:7897` 拒绝连接时**无"直连降级"**，3 次重试全败（08-13 14:08 实锤）；③ 日报"基准对照"实时联网 + **未复权** + 500 根硬编码，与策略 hfq 口径漂移。
3. **无已证实的 P0**：当前代码未发现能直接危害账本/决策正确性的缺陷；但政策源"列名变化则日期过滤静默消失"的脆弱假设一旦触发即退化为 P0 前视，需防患。

---

## 2. 问题清单

### 🔴 P1（数据正确性 / 可靠性，有实证）

#### P1-1 单一数据源单点故障（对应 IMPROVEMENTS P1-3，存量未修）
- **现象**：历史、实时、分红、交易日历全部依赖新浪一家；新浪一旦 DNS/接口/代理故障，当日所有标的被剔除或整日跳过。
- **证据**：
  - `datasource.py`：历史 `ak.fund_etf_hist_sina`（L62）、实时 `hq.sinajs.cn`（L119）、分红 `fund_etf_dividend_sina`（adjfactor.py）、日历 `tool_trade_date_hist_sina`（L177）——**无腾讯 `qt.gtimg.cn`/东财备用源**（全仓库检索无 fallback 实现）。
  - 日志 `app.log`：`2026-08-10 19:58` `NameResolutionError ... getaddrinfo failed` 3 连败；`2026-08-13 14:08` 代理 `127.0.0.1:7897` 拒绝 3 连败。
- **影响**：故障日整日不交易不结算（真实发生过至少 2 次），无人值守下累积空仓/数据缺口。
- **修复建议**：接入腾讯 `qt.gtimg.cn` 历史+实时备用源（v0.8 已实测腾讯实时可用），主源失败自动切换；或至少做"历史接口失败 → 用实时接口拼最近 N 日"的二次兜底。

#### P1-2 代理失败无"直连降级"（对应 IMPROVEMENTS 🔴 P2-10）
- **现象**：requests 走系统/环境代理 `127.0.0.1:7897`，代理拒绝连接（WinError 10061）时直接失败，**没有"绕开代理直连"的重试路径**。
- **证据**：
  - `datasource.py` 历史（L62 内 `ak.fund_etf_hist_sina`，依赖 requests `trust_env` 默认吃代理）与实时（L119 `requests.get` 未传 `proxies={}`）均无代理特判；`util.py::retry_call` 对 `ProxyError` 无特殊处理。
  - 日志 `app.log` `2026-08-13 14:08:29~36`：`ProxyError('Unable to connect to proxy', NewConnectionError("HTTPSConnection(host='127.0.0.1', port=7897)... [WinError 10061] 积极拒绝"))` 3 次重试全败。
- **影响**：用户开梯子/代理失效时行情全败 → 全天剔除；与"开梯子跑不动"的既有教训一致，且是持续复发风险。
- **修复建议**：`retry_call` 对 `ProxyError` 特判——首次捕获后改 `proxies={}`（或 `trust_env=False`）对该调用直连重试；更稳的做法是对国内行情域名配置 `NO_PROXY` 白名单（sina/tencent/东财）。

#### P1-3 日报基准"未复权 + 实时联网 + 500 根硬编码 + 失败静默"（对应 IMPROVEMENTS 🔴 P1-10）
- **现象**：日报"基准对照（买入持有）"每次生成实时联网拉新浪 500 根**原始价**，`bars[-1].close / bars[0].close` 直接算收益；策略净值却含 hfq 复权 + 货基利息 → 口径漂移；失败时 `except Exception: bench_line=""` 静默消失。
- **证据**：`reporter.py L265` `ds.fetch_daily_bars(first_sym, 500, cfg.exchange, end_date=datetime.now())`（无 `adjust=`，默认 none）；L253 附近 `except Exception: bench_line=""`；对照 `run.py run_backtest` L339-340 基准却传了 `adjust=args.adjust or settings.adjust`（回测侧同口径、日报侧不同——两处不一致实锤）。
- **影响**：除权日跳空 + 未复权 → 基准收益系统性偏低/失真，用户对比失真；账户运行超 ~2 年（>500 根）后 `first_date` 早于窗口被截断；`--report-only` 也联网，数据源挂了用户分不清"没基准"还是"拉取失败"。
- **修复建议**：基准改用本地 `bars` 表（`save_bars` 已全量缓存）+ `compute_benchmark(bars, commission_rate=...)` 并传 `adjust=hfq`（与回测/策略同口径）；失败时日报显式标注"基准获取失败（原因）"；窗口按 `first_date` 动态计算替代 500 硬编码。

#### P1-4 回测默认结束日无日历守卫（对应 IMPROVEMENTS 🔴 P1-11）
- **现象**：`_last_closed_trading_day`（`run.py L200`）用 `ds.is_trading_day` 回退找最近交易日，但 `is_trading_day` 在日历不可用时降级为"仅跳周末"（工作日一律算交易日）；无 `calendar_ok` 检查 → 节假日（清明/五一等）可能被当"最近已收盘交易日"当回测 end，与批处理侧 `calendar_ok=False` 保守跳过（`batch.py L67`）口径不一致；用户显式 `--end` 更无任何守卫。
- **证据**：`run.py L200-209`（`while not ds.is_trading_day(d)`）、`datasource.py L158 is_trading_day` 降级分支（`return date.weekday() < 5`）。
- **影响**：回测 end 落在无行情的节假日时，区间被静默截断/最后一日失真，且与真实盘口径不一致。
- **修复建议**：`_last_closed_trading_day` 检查 `ds.calendar_ok`，不可用时打印告警并回退"昨天"或提示用户显式 `--end`；显式 `--end` 也做"该日必须是有行情交易日"的校验。

#### P1-5 交易日历无本地缓存 + 无重试（对应 IMPROVEMENTS P1-4，存量未修）
- **现象**：`_load_trade_calendar`（`datasource.py L177`）仅模块级内存缓存，**无磁盘文件、无 `retry_call`**；一次网络抖动 → 空日历 → `calendar_ok=False` → 批处理保守跳过**整个交易日**。
- **证据**：`datasource.py L177-188`（单次 try/except，无重试/无落盘）；日志 `app.log` `2026-08-10 13:42`、`2026-08-10 19:58` 两处"交易日历不可用…保守跳过交易"。
- **影响**：偶发失败 = 少跑一天，且无人值守时静默；日历几乎不变，本地缓存本可彻底规避。
- **修复建议**：成功拉取后落盘 `data/trade_calendar.json`，启动先读盘再后台刷新；接入 `retry_call`；盘缓存与内存缓存互为兜底。

#### P1-6 政策源"列名变化则过滤静默消失" + 空发布时间行可绕过 cutoff（v0.22 同类隐患排查）
- **现象**：`fetch_macro_news`（`datasource.py L267`）把"发布日期==决策日"和"发布时间<=15:30"两组过滤整体包在 `if {"发布日期","发布时间"}.issubset(df.columns)`（L290）内——**一旦 akshare 改列名/少列，日期与时点过滤静默消失**，F-6 滞后、F-7 前视一并回归，且无任何告警；此外 `发布时间` 为空串的行 `""[:5] <= "15:30"` 恒真，发布日期匹配但时点未知的盘后消息可绕过 cutoff。
- **证据**：`datasource.py L290-299`（issubset 守卫 + `astype(str).str[:5] <= cutoff_time`）；`str(row.标题)`/`str(row.内容)` 对 NaN 会产出字面 `"nan"`（dtype 假设，虽当前危害小）。
- **影响**：政策版 AI 可能重新混入"上周旧闻/收盘后消息"作今日决策依据（最坏退化为已修的 P0 前视，只是当前未触发）。
- **修复建议**：列名缺省时 `logger.error` 并**返回空**（宁可无政策不引旧闻）；对空 `发布时间` 行保守丢弃（或按"早于 cutoff"处理）；加单测覆盖"列名缺省 / NaN / 空串发布时间"三类输入。

### 🟢 P2（稳健性 / 工程体验）

#### P2-1 复权"加累计分红"依赖接口"累计"语义（adjfactor）
- **现象**：`cumulative_dividend_at`（adjfactor.py）取"最后一条 `日期<=on` 的累计分红"作为加回值，**假定 `累计分红` 列是累计值**；若 akshare 改为返回单次分红，调整值静默偏小（除权跳空残留），无校验。
- **证据**：adjfactor.py `cumulative_dividend_at`/`fetch_dividends`；docstring 明确依赖"每份累计分红"语义。
- **影响**：除权日跳空未完全消除 → 特征（feature_inject）轻微失真；比例类指标影响有限。
- **修复建议**：解析时校验累计值单调不减（否则累加求和）；或升级为标准前/后复权乘数因子。

#### P2-2 N-11 bars 缓存兜底在"当日主源失败"场景被新鲜度硬校验中和（定位澄清）
- **现象**：`_fetch_and_store`（`batch.py L176`）主源失败回退 `db.get_bars`（L479）缓存，但 `run()` 的硬校验（L90 `bars[-1].datetime.date() != date.date()`）会立即把缓存旧 bar 剔除 → **当日场景下缓存兜底等于没有**（只是把 `bar_fetch_failed` 换成了 `stale_bars` 告警，当日仍整日跳过）。
- **证据**：`batch.py L176-222`（缓存回退）与 L90（硬校验）；当日缓存最新值=昨日（实查 bars 表，主源失败当天无法更新到今天）。
- **影响**：非 bug，但"兜底"名不副实——真正价值仅在 `--date` 回放 / `--catch-up` 补跑**历史交易日**时（缓存里恰好有该历史日数据）。
- **修复建议**：文档明确 N-11 定位（历史补跑容灾）；若想真兜住当日，需配合多源（P1-1）或盘中二次重试。

#### P2-3 显式 `--end=今天`（盘中）时实时补全把盘中价混入回测最后一根（A-5 残留）
- **现象**：默认 end 已被 `_last_closed_trading_day` 修掉；但显式 `--end 今天`（15:30 前）时，`fetch_daily_bars` 的实时补全会补今天盘中 bar 当收盘。
- **证据**：`datasource.py L101-107`（`bars[-1].datetime.date() < ref_date` 且实时日期==ref_date 则补）；`backtest.py` 以 bars 实际日期为交易日。
- **影响**：最后一根用盘中价当收盘，指标轻微失真（仅显式指定时触发）。
- **修复建议**：回测入口对 `end==今天且未收盘` 告警并校正为上一已收盘交易日。

#### P2-4 实时补全后 bars 数可能为 days+1，破坏"最近 days 根"契约
- **现象**：`df.tail(days)` 后再 append 实时 bar → 返回 days+1 根。
- **证据**：`datasource.py L96-107`（`bars = df.tail(days)` → `bars.append(rt)`）。
- **影响**：调用方均用 `lookback+45`，实际无碍；但契约不严谨，未来若按严格 `days` 消费会错位。
- **修复建议**：append 前若 `len(bars)==days` 先弹出最旧一根。

## 3. 做得好的地方（4 条）

1. **网络层防护到位**：`socket.setdefaulttimeout(15)`（datasource.py L19）+ 新浪域名 IPv6 过滤（L22-38）+ `retry_call` 指数退避（1s/2s/4s）接入历史/实时/分红/政策；实测今日 15:30 实时补全成功（bars 表 `510300 max_date=2026-08-13`，volume 915M 与 08-12 901M 同量级，**成交量单位一致无失配**）。
2. **"用昨日价做今日决策"被硬校验杜绝（F-1/F-2）**：`batch.py L90` 要求参与标的最新 bar 日==决策日，非决策日剔除 + 全剔除跳过；快照落 `bar_date` 供审计，失败路径（实时补全失败）也覆盖，不只是正常路径。
3. **政策源 F-6/F-7 修复完整且已生效**：决策日过滤 + 15:30 cutoff + 倒序取最新（datasource.py L290-307）；v0.22 的 `date==str` 已修为 `astype(str).str[:10]` 且 `decision_date` 兼容 date/str（L295-298）；今日日志"已获取 5 条宏观政策快讯"验证生效。
4. **复权双 bars（N-1）与日历降级守卫**：特征用本地复权（与回测 hfq 同口径）、估值/成交保持原始价，分红失败降级原始不中断批处理；`calendar_ok=False` 时工作日保守跳过（batch.py L67），杜绝节假日假快照。

## 4. 一句话总结

**数据管道"正常与失败路径"均已加固（超时/重试/硬新鲜度/去前视/复权双 bars），剩余核心风险集中在数据源与口径的单点一致性——单一新浪源、代理无直连降级、日报基准未复权，再加一条政策列名漂移的静默回归隐患，建议按 P1-1→P1-2→P1-3→P1-4→P1-5→P1-6 顺序收敛。**
