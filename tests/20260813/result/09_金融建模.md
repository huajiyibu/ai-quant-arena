## 一、结论摘要（3 条）

1. **核心金融公式全部正确，无"公式错了但看着像对"的 P0**：`rank_ic` 是货真价实的 Spearman（含并列平均秩，与 scipy 逐例一致，常数输入安全返回 0 而非 nan）；回撤面板/最大回撤/告警回撤三处统一用"逐点运行峰值、`(peak-v)/peak`"公式，"先涨后跌"验算正确；hfq 加法式复权无前视；佣金双边净口径一致（买卖、归因同一费率 0.00025）。
2. **最大问题在"口径"而非公式**：真实盘 P&L 用**原始价估值且从不贷记分红**（`batch.py:284-288` 取 `bars_map` 原始收盘价；全仓 grep 无分红入账），而回测/特征/Rank IC 用 **hfq 复权价（含分红）** → 真实盘收益系统性低估累计分红、**Rank IC 校准目标（复权含分红）与账户实际盈亏（原始价不含分红）口径不一致**；日报基准（IMPROVEMENTS P1-10，仍未勾选）未复权 + 不扣佣金 + 500 根硬编码，与回测基准口径分裂。
3. **若干 P2 级口径/健壮性瑕疵**：`profit_factor` 无亏损时返回"盈利总和（元）"（维度错误）；止损/止盈基于原始价，除权日分红跳空会假触发（当前止损默认关）；`FAIR_START_DATE` 硬编码锚点长期语义淡化；`compute_metrics` 胜率配对脆弱；利息按 252 交易日而非自然日计息。

## 二、问题清单

### P0

**未发现公式级 P0。** 本轮聚焦金融计算正确性，净值/回撤/复权/IC/利息/佣金公式均验算正确（详见"做得好"）。数据管道侧的 P0（政策 date==str 已修 v0.22、行情时效 v0.9 已修）属方向 03/07 范畴，不在本方向重复。

### P1

**P1-1 真实盘 P&L 未计入分红，且 Rank IC 校准口径（复权）与账户实际盈亏口径（原始价）不一致**
- **现象**：真实盘每日估值用 `bars_map[-1].close`（原始价）刷持仓现价（`batch.py:284-288` → `refresh_prices`），**除权日原始价自然下跌、账户却从不贷记分红现金**（`aitrader/` 全仓 grep `dividend/分红/股息` 仅出现在 `adjfactor.py`/`features.py`/`deepseek.py` 的复权与特征路径，账户/估值路径零分红入账）；而回测 `adjust=hfq` 时价格、成本、止损、forward_return、基准全部用复权价（`backtest.py:292-294`、`compute_forward_returns(buys, full)` L417 用 hfq `full`），Rank IC 真实盘回填也用复权行情（`batch.py:363` 传 `adjusted_bars_map or bars_map`）。
- **证据**：
  - `batch.py:284-288`（估值用原始 bars）；`batch.py:362-363`（IC 用复权）；`backtest.py:292-294`（回测 full 带 `adjust`）+ `backtest.py:417`；
  - `adjfactor.py:39-63`（复权=价格加回累计分红，仅影响价格序列，不影响账户现金）；
  - 数值：510300 年累计分红约 2~3%（新浪 `fund_etf_dividend_sina`，510300 共 14 条累计分红记录），真实盘持有一年原始价口径低估约该幅度；除权日（如 2025-06-18 分红 0.085）原始价跳空 -2.1%，账户市值同步"假跌"。
- **影响**：① 真实盘"做全模拟"不完整——做了货基利息（v0.16）却没做分红入账，除权日市值假跌；② Rank IC 用复权收益（含分红）校准，但账户赚的是原始价收益（不含分红），**校准目标与实际收益口径不一致**，IC 数值与账户收益不可直接对照；③ 真实盘与回测 A/B（+21.7% 等 hfq 口径）结论不可直接换算。
- **修复建议**：① 真实盘在除权日按持仓量贷记分红现金（复用 `adjfactor` 的分红表，**只用截至当日分红**保无前视），分红现金再参与货基计息——与"做全模拟"目标一致；② 至少把三处口径（真实盘/回测/IC）统一并文档化差异（README/IMPROVEMENTS），注明"真实盘收益为原始价不含分红"。

**P1-2 日报基准与回测基准口径不一致（IMPROVEMENTS P1-10，仍未修）**
- **现象**：日报基准 `reporter.py:265` `fetch_daily_bars(first_sym, 500, cfg.exchange, end_date=datetime.now())`——**不传 `adjust`（原始价）、500 根硬编码、不扣佣金**、`end_date=now`（盘中/周末会混入实时 bar 或停在最近交易日）；而回测基准 `run.py:340` 传 `adjust=hfq` + `compute_benchmark(..., commission_rate=settings.risk.commission_rate)`（`run.py:345-347`）扣佣金。
- **证据**：
  - `reporter.py:265`（日报基准原始价、无佣金、硬编码 500）；`run.py:340,345-347`（回测基准 hfq + 扣佣）；
  - `docs/IMPROVEMENTS.md` L26/L141-148/L246（P1-10 未勾选，同款描述）。
- **影响**：日报"基准对照（510300 买入持有）"与账户（真实盘原始价 + 含佣金 + 货基利息）及回测基准（hfq）三者口径各异，收益数字不可横向比较，可能误导小白用户；网络失败时 `except Exception: bench_line=""` 静默留空，用户无从察觉基准缺失。
- **修复建议**：日报基准改本地 bars + 与账户同口径（真实盘用原始价 + 扣单边买入佣金，或与回测统一 hfq 并显式标注口径），`end_date` 用最近已收盘交易日；失败时在日报显示"基准不可用"而非静默留空（对应 IMPROVEMENTS P1-10 验收）。

### P2

**P2-1 `profit_factor` 无亏损时返回"盈利总和（元）"，维度错误**
- **现象**：`compute_metrics`（`backtest.py:121-125`）`gross_loss==0` 时 `profit_factor = gross_profit`（即所有盈利的**元**总和），被当作"盈亏比"展示；如全赢 2 对盈利 300 元 → 显示"盈亏比 300.00"（实为 300 元，非倍数）。
- **证据**：数值验算——全赢 2 对 `profit_factor=300.00`；一赢一亏（毛利 400/毛损 200）正确显示 2.00；`PREDICTION_IMPROVEMENTS.md` A/B 表里"盈亏比 24.13"是含亏损的样本，若某策略 100% 胜率将显示为元。
- **影响**：全赢/无亏损策略的盈亏比展示为错误量纲，看似"很高"实则无意义；日报/回测报表的盈亏比列对无亏损区间失真。
- **修复建议**：无亏损时返回 `inf`/`None`（报表显示"∞"或"—"），或在回测/日报明确"毛损=0 时盈亏比未定义"。

**P2-2 止损/止盈基于原始价，除权日分红跳空会假触发（真实盘）**
- **现象**：`apply_stop_rules`（`portfolio.py:84-105`）用 `price/cost_price`（原始价 vs 原始成本）判触发；真实盘除权日原始价跳空（如分红 0.085 → 单日 -2.1%），若 `stop_loss_pct` 开到 2% 会**把分红除权误判为止损**；回测 `adjust=hfq` 价格连续，无此问题 → 真实盘与回测止损行为不一致。
- **证据**：`portfolio.py:96-104`；真实盘止损成交价走当日收盘、回测走 next_open+滑点（`batch.py:336` vs `backtest.py:381`）；数值：`price=4.0, 分红 0.085` → 除权日原始价 ≈3.915 → `pnl_pct≈-2.1%`。
- **影响**：当前 `config.json` risk 块未暴露 `stop_loss_pct`（默认 0 关），暂不触发；一旦开启，除权日可能错误清仓；且与回测口径漂移。
- **修复建议**：止损/止盈的触发基准改复权价（与回测一致），或对除权日豁免；至少文档化"真实盘止损=原始价基准、回测=复权价基准"。

**P2-3 `compute_metrics` 胜率/盈亏比配对脆弱（amount 式"最后一次买入"配对）**
- **现象**：`backtest.py:104-118` 按 `buys[symbol]=t["amount"]`（最后一次买入金额）配对，卖出时 `pnl = sell_amount - buys.get(symbol, 0.0)`。本系统约束（单标的单持仓、整仓卖出、`already_holding` 拒绝重复加仓）下买→卖严格交替，配对恰好正确；但**一旦未来支持加仓/部分卖出即静默算错**（数值演示：买5000+买3000→卖10000 算出 pnl=7000、盈亏比 7000.00，忽略首笔 5000）；卖无对应买时 `buys.get(symbol,0)` 把卖出全额当利润。
- **证据**：`backtest.py:105-118`；数值验算场景 2 输出 `win_rate=1.00 盈亏比=7000.0000`。
- **影响**：当前正确（已验证 buy→sell→buy→sell 双对净额 99.50/99.00 全部正确配对），属"公式对但结构脆弱"；与 `attribution.closed_trade_pairs`（FIFO、按股数配对）逻辑重复且不一致。
- **修复建议**：`compute_metrics` 胜率/盈亏比复用 `attribution.closed_trade_pairs` 的 FIFO 配对，一处实现、两处口径统一；加"无匹配买入的卖出不计入"守卫。

**P2-4 `FAIR_START_DATE` 硬编码锚点：不漂移但长期语义淡化 + fallback 起点风险**
- **现象**：`reporter.py:13` 硬编码 `FAIR_START_DATE="2026-08-10"`；`_fair_snapshots`（`reporter.py:16-21`）先取 `date>=FAIR` 且 `bar_date` 非空，空时回退到 `valued`（各账户**首个** bar_date 非空快照）。硬编码本身保证不随数据漂移（v0.21 目标达成），但 fallback 分支理论上会回到 v0.21 前"各账户起点日期不同"的旧行为；长期运行后 08-10 作为"公平起点"语义逐渐失真。
- **证据**：备份库三账户验算——rule/ai/ai_policy 的 `fair_dates` 均 = `['2026-08-10','08-11','08-12','08-13']`，`fair_base` 分别为 999875.05/1001194.73/999923.56；**ai 引擎出现"符号翻转"（真实 `+554.70` vs 公平 `-640.03`）**，v0.21 已把主字段改为真实累计盈亏、公平口径降为副注（`reporter.py:24-38,104-110,138-144`），当前展示不会误导。
- **影响**：当前不漂移（快照都 ≥08-10，fallback 分支实际不可达）；仅长期语义淡化 + fallback 属理论死代码。
- **修复建议**：锚点改为显式配置（config 或环境变量）+ 文档化"公平对比自 X 起归一"；或删除 fallback 分支并断言快照存在，避免未来误导。

**P2-5 利息按 252 交易日计息、周末/节假日不计息（复利口径与真实货基有出入）**
- **现象**：`apply_cash_interest`（`portfolio.py:69-81`）`daily_rate=年化/252`，仅在交易日逐日复利；真实货基按自然日（365）计息。
- **证据**：数值验算——252 交易日复利有效年化 **1.7145%**，365 自然日复利 **1.7144%**，差异 ≈0.01pp（因利率仅 1.7%，可忽略）；`cash_interest_rate=0.017` 默认（`config.py:74`，config.json 已设）；单利名义 1.70%。
- **影响**：金额极小（百万本金一年差 ~0.5 元），不构成实质偏差；"货基利息累计"（日报）口径 = 交易日复利，与真实货基（自然日）略有出入，属建模简化。
- **修复建议**：文档化"按 252 交易日复利（近似 365 自然日）"；若要精确可改 `rate/365` 并在非交易日补计息（当前收益影响可忽略，优先级最低）。

**P2-6 归因/反馈佣金率硬编码 0.00025，与 config 漂移风险**
- **现象**：`attribute_trades`/`closed_trade_pairs` 默认 `commission_rate=0.00025`（`attribution.py:20,64`），但调用方 `reporter.py:201`（日报归因）、`batch.py:138-139`（反馈）、`backtest.py:360-362`（反馈）**均未传入 `settings.risk.commission_rate`** → 一旦 config.json 改佣金率或回测 `--commission-mult`，归因/反馈仍用硬编码 0.00025，与执行口径（`risk.commission_rate`，`risk.py:60`/`portfolio.py:180`）漂移。
- **证据**：`attribution.py:20,64`（默认参数）；`reporter.py:201`、`batch.py:138-139`、`backtest.py:360-362`（调用未传）；config.json `commission_rate=0.00025`（当前相等，风险仅在改配置后）。
- **影响**：当前三处费率一致（0.00025），无实际偏差；属配置耦合风险（P0-2"口径漂移"同类）。
- **修复建议**：归因/反馈的佣金率由调用方显式传 `settings.risk.commission_rate`（或从 Settings 注入），删除硬编码默认。

**P2-7 持仓浮盈 `unrealized_pnl` 不含买入佣金；归因只统计已平仓**
- **现象**：`models.py:44-45` `(last_price-cost_price)*volume`，`cost_price` 为成交价（不含佣，`portfolio.py:24`），买入佣金已从现金扣除（`risk.py:60` `cost` 含佣）但未进成本 → 浮盈高估 ~0.025%×仓位；`attribute_trades`（`attribution.py:52-60`）只聚合已平仓 FIFO 配对，未平仓不计入。
- **证据**：`models.py:44-45`；`portfolio.py:20-25`（cost_price=price）；数值：买 1000 股@1.0 含佣成本 1000.25，浮盈口径 `(1.05-1.0)*1000=50`，真实净利 `49.75`。
- **影响**：金额微小；日报持仓卡片不展示浮盈，用户看不到未实现盈亏——属展示缺口非公式错误。
- **修复建议**：可选把买入佣金计入 `cost_price`（成本基含佣），或文档化"浮盈为不含佣毛口径、归因/已实现为净口径"。

## 三、做得好的地方

1. **`rank_ic` 是真 Spearman（非误用 Pearson/错位）**：含并列平均秩实现（`backtest.py:162-185`），与 `scipy.stats.spearmanr` 在单调/反向/并列/完全相关等 6 组样例上**逐例一致**（含并列组 `+0.948683` 精确匹配）；常数输入（如 rule 恒 0.5）返回 0.0 而非 nan，避免脏值污染日报。`compute_forward_returns`/`_calibrate_forward_returns` 用 `bisect_right` + 决策日收盘 → 决策日后 20 交易日，两处逻辑一致、无前视；P0-5 已把 IC 样本限定为**实际成交**的 buy。
2. **回撤三处口径统一且正确**：`plot_backtest_curves` 面板（`reporter.py:349-355`）、`compute_metrics.max_drawdown`（`backtest.py:78-86`）、`check_alerts` 告警（`notify.py:32-35`）统一用"逐点运行峰值、`(peak-v)/peak`"，分母=峰值；"先涨后跌 100→110→90"验算 18.18% 正确、v0.19 已修告警传单元素快照的回归。
3. **佣金双边净口径一致、净佣金统一为 0.00025**：买入成本含佣（`risk.py:60` `cost=vol*price*(1+comm)`）、卖出净额扣佣（`portfolio.py:180`）、归因扣双边佣金（`attribution.py:46-49`），与 config 一致；回测基准 `compute_benchmark` 已扣买入佣金（PP-1 落地），避免 P2-12 偏袒基准的旧缺陷。
4. **hfq 加法式复权正确且无前视**：`P_adj(t)=P(t)+截至 t 累计分红`（`adjfactor.py:39-63`），只用截至当日分红；数值验证除权日 3.86+0.085=3.945 与除权前 3.95 连续、消除跳空；回测内价格/成本/止损/基准/forward_return 全部同 hfq 一致。

## 四、一句话总结

净值、回撤、Spearman IC、hfq 复权、双边佣金等**核心公式全部正确**，本轮最值得修的是**口径一致性**：真实盘从不贷记分红（P&L 低估 + IC 校准目标与账户实际盈亏错配）与日报基准未复权（P1-10），其次是无亏损盈亏比量纲、除权日止损假触发等 P2 打磨项。
