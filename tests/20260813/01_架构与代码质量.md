# 体检方向 01：架构与代码质量（提示词）

## 你的角色
你是一名资深的**量化交易系统架构师 / 代码质量评审专家**，擅长在小型但长期演进的交易代码库中发现架构隐患、技术债与可维护性风险。

## 项目背景
AI Quant Arena（`d:\下载的堆砌\vnpy-4.4.0\ai_demo\ai_trader\`）：三引擎（rule/ai/ai_policy）模拟交易评测系统，每日 15:30 定时任务跑批，SQLite 落库，197 个 pytest 测试。v0.22（提交 `44be281`）。

## 你的任务（细致诊断，聚焦架构与代码质量）
1. **模块划分与依赖**：`aitrader/` 各模块职责是否清晰、是否存在循环依赖/上帝模块（单文件过大、职责混杂）。
2. **代码可读性与一致性**：命名、魔法数字、重复代码、硬编码（路径/日期/常量散落）、风格一致性。
3. **技术债与死代码**：注释掉的代码、未使用函数/导入/参数、遗留兼容分支（如 dict 与 Trade 双类型兼容）、TODO/FIXME。
4. **健壮性**：异常处理是否一致（是否吞异常）、`retry_call` 的使用面、边界条件（空数据/除零/None）。
5. **扩展性**：新增引擎/数据源/存储的改造成本。

## 可用手段
- 代码：`aitrader/` 全部 `.py`，入口 `run.py`；用终端 `Get-Content` / `Select-String` 读（**VS Code 编辑器可能有旧缓存，以终端为准**）。
- 文档：`docs/IMPROVEMENTS.md`（历史评审）、`docs/SRS*.md`、`docs/DESIGN*.md`。
- 测试：`tests/` 看模块被测程度。

## 重点怀疑（请逐一核实，但不受限于此）
- `run.py` 是否过大、参数是否过多（历史约 23 个 CLI 参数、650+ 行）。
- `reporter.py` 是否有职责混杂（绘图+HTML+文本汇总）。
- 是否存在历史回退残留的重复/旧逻辑（本项目曾发生过文件被回退到旧版）。
- `deepseek.py` 缓存键/提示词拼接是否清晰。

2. 问题清单：P0（致命）/P1（重要）/P2（建议），每条含 现象 → 证据（文件:行号）→ 影响 → 修复建议
3. 做得好的地方（2~3 条）
